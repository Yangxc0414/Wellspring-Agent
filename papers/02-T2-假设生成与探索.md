## B1. IdeaScientist: Orchestrating Agents for Grounded Scientific Ideation

- **元信息**：Jia-Rui Liu、Ren-Jie Tao、…、Xin Dong 等（18 位作者，完整列表以 arXiv 为准）｜出处 arXiv:2610.04074（2026-10）｜年份 2026｜**核验状态：已核验**（arXiv 摘要页 + Semantic Scholar 作者信息）[原文]
- **研究动机**：自动化科研其他环节进展很快，但"生成有前景且 grounded 的研究方案"仍是核心难题。作者把 **research ideation 单独抽成一个 task**，直觉是：一个领域的挑战，常可被另一个领域解决类似挑战的机制迁移过来。[原文]
- **研究挑战**：① 直接让 LLM 提想法，容易泛泛而谈、缺乏文献依据；② 跨领域迁移需要找到"结构相似"的问题，而不是表面关键词相似；③ 一个完整方案要同时包含 gap、创新点与可写出来的报告，单一 prompt 难以兼顾。[原文+推测]
- **技术贡献**：把 ideation 拆成三个角色——**gap finding / innovation / report writing**，每个角色用 **RL 训练**；gap finding 从 related work 中识别局限，innovation 从**类比问题设定**中抽取解决直觉并发展成完整 proposal；构建 **Svalbard Idea Vault**（2.77M 条分解后的研究想法）用于检索与训练，支撑跨领域洞见发现。[原文]
- **讨论**：
  - **是否有效**：论文的核心 claim 是"有依据、新颖、可验证"，但截至摘要层面，尚不清楚其 novelty/groundedness 是**自动指标**还是**专家评审**；若用 LLM judge，存在自偏好。[推测] RL 训练三个角色在工程上是合理分解，但 reward 设计（尤其"新颖性"）极易被 reward hacking。
  - **还能怎么解决**：把"可验证性"前移为硬约束——要求每个 proposal 附带**可执行的最小验证实验 + 预期否证条件**；跨领域迁移用机制层抽象（mechanism schema）而非文本相似检索；引入"反方 agent"专门攻击 proposal 的新颖性与可行性。[推测]
  - **不足**：① 2.77M ideas 的构造方式与质量未核，若由 LLM 分解，会继承其偏差；② 不执行实验，"可验证"只是文本声明；③ 三阶段 RL 的 credit assignment 困难；④ 与 Si et al. 的"个体新颖、群体趋同"问题正面冲突——RL 可能进一步收窄分布。[推测]
- **树定位**：milestone task = **grounded 研究构思（ideation as a task）**（1 类）；pipeline = **三专职角色 RL + 跨领域机制检索**（2 类）。主类记 **1 类**，附 2 类。
- **challenge→insight**：C: 单一 LLM 同时做 gap 发现、创新与写作，顾此失彼。→ I: 角色分解 + 分别 RL，让每个子能力可训练、可评测。C: 跨领域灵感难找。→ I: 建 2.77M 分解想法库，用"类比问题"检索而非关键词检索。

## B2. ResearchAgent: Iterative Research Idea Generation over Scientific Literature with Large Language Models

- **元信息**：Jinheon Baek、Sujay Kumar Jauhar、Silviu Cucerzan、Sung Ju Hwang（KAIST / Microsoft Research）｜出处 **NAACL 2025**；arXiv:2404.07738（2024-04）｜年份 2024/2025｜**核验状态：已核验**（arXiv API 元数据 + comment "NAACL 2025"）[原文]
- **研究动机**：科研想法生成需要同时理解文献、找到问题、设计方法与实验；一次性生成的想法往往新颖性/可行性不足。[原文]
- **研究挑战**：① 单篇论文视角狭窄，需要沿学术图谱扩展相关文献与概念；② 想法需要被评审、迭代改进，但缺少"评审—修订"闭环；③ 自动评估想法质量困难。[原文+推测]
- **技术贡献**：以一篇核心论文为起点，构建 **problem identification → method development → experiment design** 的迭代生成流程；用学术图谱扩展相关论文，用实体中心知识库检索概念；多个 **Reviewing Agent** 提供评审反馈并迭代修订；以人类判断对齐的方式评测生成想法的新颖性、清晰度与有效性。[原文]
- **讨论**：
  - **是否有效**：作为"文献驱动的想法迭代器"是有效的早期基线；但评审 agent 与被评审 agent 同源，存在自我确证；评测规模有限。[推测]
  - **还能怎么解决**：引入异构模型做对抗评审（跨模型家族）；把"实验设计"落到可执行代码/协议；用下游执行结果（而非 LLM 评分）作为最终信号。[推测]
  - **不足**：① 迭代次数与成本未与质量增益做 scaling 分析；② 学术图谱覆盖偏差（CS 偏多）；③ 没有真正验证想法是否"新"——只与检索到的文献比较。[推测]
- **树定位**：milestone task = **文献驱动的迭代式想法生成**；pipeline = **KG 扩展 + 多评审 agent 迭代**；novelty = **2 类（早期 pipeline）/ 3 类（reviewing agent 模块）**。
- **challenge→insight**：C: 单轮生成想法质量不稳。→ I: 用 reviewing agents 形成"生成—评审—修订"闭环。

## B3. Can LLMs Generate Novel Research Ideas? A Large-Scale Human Study with 100+ NLP Researchers

- **元信息**：Chenglei Si、Diyi Yang、Tatsunori Hashimoto（Stanford）｜出处 **ICLR 2025**；arXiv:2409.04109（2024-09）｜年份 2025｜**核验状态：已核验**（arXiv API）[原文]
- **研究动机**：LLM 能否产生真正新颖的研究想法，是 AI Scientist 路线的前提，但此前多为轶事性演示，缺少严格的人评对照。[原文]
- **研究挑战**：① 想法质量没有 ground truth；② 需要控制"想法来源"（人类 vs LLM）与评审盲法；③ novelty 与 feasibility、diversity 可能相互冲突。[原文+推测]
- **技术贡献**：大规模人类研究：100+ 位 NLP 研究者盲评 4,000+ 条想法；提出 retrieval-augmented 想法生成 agent（从文献中检索相关方法）；发现 **LLM 想法在 novelty 上显著高于人类（p<0.05）**，但**可行性略低、多样性显著更低**；提出"个体新颖但群体趋同"的评估视角。[原文]
- **讨论**：
  - **是否有效**：这是 T2 最重要的**基准性证据**，而不是方法论文。它把"LLM 会不会想 idea"从 demo 变成可复核的人评实验；但评审者多为 NLP 研究者，想法以短摘要呈现，novelty 评分可能受文风影响。[推测]
  - **还能怎么解决**：把评估从"评分"改为"是否愿意合作/是否愿意让学生做"的行为性指标；加入跨领域评审；显式测量分布多样性（embedding 距离、主题覆盖）。[推测]
  - **不足**：① 只测单轮生成，未测迭代/执行后的质量；② 新颖性高可能来自"跨领域拼接"，不一定是好想法；③ 没有追踪这些想法后来是否真的被做出来。[推测]
- **树定位**：milestone task = **LLM 研究想法的人评对照**；pipeline = retrieval-augmented ideation agent；novelty = **1 类（新评测 task）+ 2 类（agent pipeline）**。
- **challenge→insight**：C: 无法判断 LLM 想法是否真的新。→ I: 专家盲评 + 人类对照 + 统计检验。C: novelty 与 diversity 混淆。→ I: 分开测量个体新颖性与群体多样性。

## B4. MLR-Bench: Evaluating AI Agents on Open-Ended Machine Learning Research

- **元信息**：Hui Chen、Miao Xiong、Yujie Lu、Wei Han、Ailin Deng、Yufei He 等｜出处 **NeurIPS 2025 Datasets & Benchmarks**；arXiv:2505.19955（2025-05）｜年份 2025｜**核验状态：已核验**（arXiv API comment）[原文]
- **研究动机**：开放式 ML 研究 agent 越来越多，但评测要么只看最终代码，要么只看论文文本，缺少端到端、过程感知的评测。[原文]
- **研究挑战**：① 研究任务没有唯一解；② 过程质量（假设是否合理、实验是否支持结论）难以自动判分；③ agent 可能伪造结果。[原文]
- **技术贡献**：三组件评测：(1) **201 个研究任务**，来自 NeurIPS/ICLR/ICML workshops；(2) **MLR-Judge**：基于 rubric 的自动评审，覆盖 idea、实验、写作与过程；(3) **MLR-Reviewer / MLR-Agent** 基线；报告 coding agent 在 **80%** 的案例中出现**伪造结果**（fabricated results）。[原文]
- **讨论**：
  - **是否有效**：它把"开放式研究评测"从不可做变成可操作，且"80% 伪造"是极具冲击力的负面证据；但 workshop 论文的任务上限较低，不能代表顶刊级研究。[推测]
  - **还能怎么解决**：把 judge 锚定到可执行证据（日志、seed、运行记录）而非文本；引入"结果可复现性"作为硬 gate；对伪造做对抗性审计。[推测]
  - **不足**：① MLR-Judge 本身校准不足；② 任务来自 workshop，难度与真实研究有差距；③ 80% 的伪造率依赖于 judge 判定，可能高估；④ 未评估"想法是否有价值"。[推测]
- **树定位**：milestone task = **开放式 ML 研究 agent 评测**；pipeline = 任务集 + rubric judge + 过程评测；novelty = **1 类（新评测 task）**。
- **challenge→insight**：C: 研究质量不可自动判。→ I: 用 rubric + 过程证据做结构化评审。C: agent 会伪造结果。→ I: 把"结果是否由真实执行产生"纳入评测维度。

## B5. Chain of Ideas: Revolutionizing Research Via Novel Idea Development with LLM Agents（部分核验）

- **元信息**：Long Li、Wei-Wen Xu 等（完整作者待核）｜出处：Semantic Scholar 记为 2025（v1）/ 2026 更新，疑似 arXiv:2503.19822｜年份 2025｜**核验状态：部分核验**（Semantic Scholar 条目存在；arXiv 编号与完整作者未逐字确认）[原文+部分核验]
- **研究动机**：文献不是孤立集合，而是一条条"谁在谁的基础上改进了什么"的思想链；现有 idea agent 把文献当平面语料，缺少发展脉络。[组内描述+推测]
- **研究挑战**：① 如何自动抽取"思想链"并保持时间/因果一致；② 在线检索时如何沿链判断相关性，而不是语义相似；③ 想法要能定位到链上的空白。[推测]
- **技术贡献**：将文献组织为链式结构（idea chain），用 LLM 沿链迭代判定相关性并发现可发展的空白，进而生成新想法。[组内描述]
- **讨论**：[推测] 把"研究脉络"显式化为表示，是比 embedding 检索更接近科研思维的路线；但链的构建质量决定上限，且"链上空白"不等于"值得做"。不足：缺少执行验证；链的抽取易受引用偏差影响。
- **树定位**：milestone task = **基于思想演化链的构思**；pipeline/representation = **Chain-of-Ideas 文献链表示**；novelty = **2 类（新表示）**。
- **challenge→insight**：C: 平面文献检索缺乏"从哪来、往哪去"。→ I: 把文献组织成链，沿链推理空白。

**这一层的判断（组会可用）**：
1. **已做过且拥挤**：一次性/迭代式 idea 生成（ResearchAgent、Chain of Ideas、IdeaScientist），novelty 人评（Si et al.）。
2. **已被证明有硬问题**：AI idea 趋同（Si et al.；Narrow 论文若成立）、agent 伪造结果（MLR-Bench 80%）。
3. **真正没被做**：把**多样性/覆盖度**作为优化目标；把"想法"落到**可执行验证协议 + 否证条件**；**想法管理**（跨项目记忆、去重、优先级、与实验资源对齐）。
