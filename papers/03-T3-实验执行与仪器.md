## C1. SciToolAgent: A Knowledge Graph-Driven Scientific Agent for Multi-Tool Integration

- **元信息**：Ke-Yan Ding、Jing Yu、Junjie Huang、Yuchen Yang、Qiang Zhang、Hua-Jun Chen 等（浙江大学 HICAI 团队）｜出处 **Nature Computational Science**（2025-07；DOI: 10.1038/s43588-025-00849-y）｜年份 2025｜代码：github.com/HICAI-ZJU/SciToolAgent｜**核验状态：已核验**（Nature 子刊页面 + 官方报道 + GitHub）[原文]
- **研究动机**：现代科研依赖大量高度专业化计算工具，但用好它们需要深厚领域知识；LLM 虽有工具调用能力，却难以在复杂科学工作流中**无缝集成与协同调度多种工具**（工具依赖、版本兼容、输入输出格式、安全性）。[原文]
- **研究挑战**：① 工具数量大（500+），靠 in-context learning 无法刻画工具间关系；② 工具链规划错误会在后续步骤被放大；③ 科学工具可能产生危险操作，需要安全审查。[原文]
- **技术贡献**：构建 **SciToolKG**（科学工具知识图谱：输入/输出、功能、依赖、安全等级）+ **规划器—执行器—总结器**三组件 agent；用**图检索增强生成**选择工具链，按序执行并支持重试；内置**安全检查模块**（对照安全防护数据库）；在 **SciToolEval（531 个科学问题）**上整体准确率约 **94%，比当时 SOTA 高约 10%**；蛋白质工程、化学反应性预测、化学合成、MOF 筛选四类案例。[原文]
- **讨论**：
  - **是否有效**：在"工具编排准确性"上有效，且案例覆盖生物/化学/材料三个域；但本质是**计算工具编排**，不涉及湿实验执行，工具调用失败后的科学语义纠错能力有限。[原文+推测]
  - **还能怎么解决**：把工具图谱升级为"能力—约束"本体，支持自动发现/接入新工具（其后续 SciToolAgent-Evo 就在做自演化）；用执行轨迹训练规划器；把安全审查从黑名单升级为参数级风险模型。[推测]
  - **不足**：① 工具与任务集由作者构建，存在选择偏差；② 531 题的"最终答案准确率"依赖参考答案，开放式任务未覆盖；③ 知识图谱维护成本高，新工具需人工建模；④ 安全模块是规则式的，难以覆盖未知风险。[推测]
- **树定位**：milestone task = **多工具编排的科研 agent**（3 类模块集成为主，但 SciToolEval 是 1 类评测 task）；pipeline = **KG-RAG 工具规划 + 执行 + 安全审查**；novelty = **2 类（pipeline）/ 1 类（工具编排 benchmark）**。
- **challenge→insight**：C: 工具太多、关系复杂，LLM 规划易错。→ I: 把工具关系做成知识图谱，用图检索约束规划空间。C: 科学工具操作有风险。→ I: 在规划与执行之间插入安全审查模块。

## C2. BioDiscoveryAgent: An AI Agent for Designing Genetic Perturbation Experiments

- **元信息**：Yusuf Roohani、Andrew Lee、Qian Huang、Jian Vora、Zachary Steinhart、Kexin Huang、Alexander Marson、Percy Liang、Jure Leskovec（Stanford）｜出处 **ICLR 2025**；arXiv:2405.17631（2024-05，v3 2025）｜年份 2025｜代码：待查（项目页）｜**核验状态：已核验**（arXiv HTML + 引用列表注明 ICLR 2025）[原文]
- **研究动机**：基因扰动实验的设计空间巨大（选哪些基因、什么组合、如何迭代），湿实验一轮成本高；能否让 LLM agent 仅凭生物学知识与工具，**闭环地提出下一轮扰动实验**，并在有限轮次内发现目标表型？[原文]
- **研究挑战**：① 需要从文献/数据库中综合基因功能知识；② 每轮只能做少量实验，必须主动学习；③ 缺少可复现的评测环境（湿实验不可反复）。[原文+推测]
- **技术贡献**：BioDiscoveryAgent = LLM + 工具（文献检索、基因信息、数据库查询）+ 实验选择策略；在**虚拟基因扰动实验环境**中评测多轮主动学习式的实验设计；与人类专家设计的实验方案做对比；论文报告其在发现目标基因/组合上的效率优于若干基线（含无工具版本）。[原文]
- **讨论**：
  - **是否有效**：它证明了"LLM 先验 + 工具"可以在**模拟环境**里做主动实验设计，且不做模型训练；但虚拟环境与真实湿实验之间的 sim2real gap 是核心疑问。[原文+推测]
  - **还能怎么解决**：把不确定性显式建模（贝叶斯主动学习）与 LLM 先验结合；引入实验失败模式（污染、脱靶）作为约束；在真实湿实验中小规模验证。[推测]
  - **不足**：① 评测依赖模拟器，模拟器的偏差决定结论；② 工具调用错误会污染假设；③ 未覆盖多基因组合爆炸的真实规模；④ 人类对比的样本量有限。[推测]
- **树定位**：milestone task = **闭环基因扰动实验设计**；pipeline = **LLM + 工具 + 多轮实验选择**；novelty = **1 类（新 task）/ 2 类（pipeline）**。
- **challenge→insight**：C: 湿实验轮次有限、搜索空间巨大。→ I: 让 agent 每轮用文献先验 + 已有结果选下一批实验，形成主动学习闭环。

## C3. An agentic artificially intelligent X-ray scientist

- **元信息**：Zhantao Chen、A. N. Petsch、A. J. Israelski 等（Stanford / SLAC）｜出处 **Nature Machine Intelligence**（2026；DOI: 10.1038/s42256-026-01261-5）｜年份 2026｜代码/数据：Zenodo 开源｜**核验状态：已核验**（Nature MI 页面 + 多家报道）[原文]
- **研究动机**：大科学装置（同步辐射光源）上的实验仍需大量人工监督；固定脚本难以应对样品偏差、设备漂移、信号波动等真实异常。目标是让 LLM agent 在真实光束线上**自主完成多步实验**。[原文]
- **研究挑战**：① 真实仪器接口与安全规程复杂；② 观测是图像化的（探测器图、扫描曲线），需要定性判读；③ 虚拟环境与真实装置存在未建模偏差（装夹误差、~1.22° 隐藏电机偏移）。[原文]
- **技术贡献**：三层架构：**LLM 决策 + MCP 工具层 + 实验设备**；先在**虚拟光束线**（Python 模拟六圆衍射仪、峰形展宽、探测器缺陷）中开发，再原样迁移到 **SSRL BL17-2**；任务为单晶取向矩阵求解（Co3Sn2S2），agent 自主选峰、扫电机、读图、拟合、纠错；在真机上识别并修正约 **1.22°** 的意外 η 偏移；人工仅作为"安全中介"粘贴命令；Gemini 2.5 Flash / Claude Sonnet 4 为底座，多数运行对齐误差 <5°。[原文]
- **讨论**：
  - **是否有效**：是"agent 能在真实大装置上闭环做实验"的强证据；但任务只是**样品对准**（单晶散射的前置步骤），真机试验次数有限，尚非统计意义上的定论。[原文]
  - **还能怎么解决**：把"元 agent"用于自动生成/优化各仪器的引导提示，降低迁移成本；加入在线校准与故障恢复策略库；把实验日志变成可复用技能。[原文+推测]
  - **不足**：① 任务窄（对准），不能代表完整实验；② 仍需人类粘贴命令（安全中介），自治度受限；③ 真机样本少、跨装置泛化未验证；④ 依赖昂贵的专有模型与设施机时。[推测]
- **树定位**：milestone task = **真实科学仪器上的自主实验**；pipeline = **虚拟装置预训练 → MCP 工具调用 → 真机闭环**；novelty = **1 类（新 task）/ 2 类（sim-to-real 仪器 agent pipeline）**。
- **challenge→insight**：C: 真实装置不允许随意试错。→ I: 先在可加噪声的虚拟光束线里练，再原样迁移，只加接口适配。C: 真实误差未被建模。→ I: 让 agent 把探测器图当图像读、根据观测反推状态，而不是照搬理论值。

## C4. AutoLabs: cognitive multi-agent systems with self-correction for autonomous chemical experimentation

- **元信息**：G. U. Panapitiya、E. G. Saldanha、H. M. Job、O. R. Hess（PNNL）｜出处 **Scientific Reports** 16:19554（2026-09）；arXiv:2509.25651（2025-09）｜年份 2025/2026｜代码：github.com/pnnl/autolabs｜**核验状态：已核验**（PNNL 页面 + Nature Scientific Reports）[原文]
- **研究动机**：自主化学实验需要多智能体协作 + 对失败的自纠正；现有系统多为固定工作流，遇到异常无法自我修复。[原文]
- **研究挑战**：① 化学实验步骤的参数空间与安全约束；② 需要把自然语言目标翻译为可执行协议并监控执行；③ 出错后要能定位并重规划，而不是整轮报废。[原文+推测]
- **技术贡献**：认知多智能体架构（规划、执行、分析等角色）+ **self-correction 循环**；对接自动化化学实验硬件（报道提到 Unchained Labs 商品化设备）；展示自主实验设计与优化案例。[组内描述+原文]
- **讨论**：[推测] 工程完整度高、有真实硬件闭环；但"self-correction"的触发与归因是否可靠、错误会不会被掩盖，需要看消融；化学覆盖面与任务难度有限。作为"产业可落地形态"的参照比作为方法创新更有价值。
- **树定位**：milestone task = **自主化学实验闭环**；pipeline = **认知多智能体 + 自纠正 + 商品化硬件**；novelty = **2 类（系统 pipeline）/ 3 类（self-correction 模块）**。
- **challenge→insight**：C: 实验异常导致整轮失败。→ I: 让多个角色各自检查并触发局部重规划（self-correction cycle）。

## C5. Robin: A Multi-Agent System for Automating Scientific Discovery（Nature 版：A multi-agent system for automating scientific discovery）

- **元信息**：Ali Essam Ghareeb、Benjamin Chang、Ludovico Mitchener、Angela Yiu、Caralyn J. Szostkiewicz、Jon M. Laurent 等（FutureHouse / Edison Scientific）｜出处 **Nature**（2026-05/07；arXiv:2505.13400 预印本 2025）｜年份 2025/2026｜代码：FutureHouse 平台（Crow/Falcon/Finch 等）｜**核验状态：已核验**（Nature 报道 + arXiv 摘要）[原文]
- **研究动机**：科学发现是"背景调研 → 假设 → 实验 → 数据分析"的迭代，但此前没有系统能把这些阶段串成一个 workflow。作者要建一个**多智能体系统**，端到端自动化实验生物学中的假设生成与数据分析。[原文]
- **研究挑战**：① 文献检索、假设生成、实验设计、数据分析各自需要不同工具；② 湿实验结果必须回流改写下一轮候选，闭环难；③ 需要真实生物学验证，而不是只写论文。[原文]
- **技术贡献**：专用 agent 分工（Crow 快速文献问答、Falcon 深度检索、Owl 新颖性核查、Phoenix 实验规划、Finch 代码/数据分析）+ 上层编排；输入一个疾病名，输出机制假设、候选药物、实验方案；团队在干性 AMD 上识别 **ripasudil（ROCK 抑制剂）** 为候选，并提出**昼夜节律 → RPE 吞噬作用**的新机制；湿实验由人类完成，结果回流给 Robin 解析并生成下一轮候选；从立项到投稿约 2.5 个月。[原文]
- **讨论**：
  - **是否有效**：这是"AI 提出可检验假设 + 真实湿实验验证 + 同行评审"的完整证据链，是 L2 的里程碑；但实验执行仍由人做，属于**半自主**；只验证了一种疾病，ripasudil 是已知药物重定位，机制新颖但临床距离远。[原文+推测]
  - **还能怎么解决**：把湿实验设备接入（与自驱动实验室结合）；让 agent 显式维护"证据—假设"图并标注不确定性；增加失败假设的负结果记录。[推测]
  - **不足**：① 单一疾病、单条成功路径，存在发表偏差；② LLM 的文献综合可能漏掉关键反证；③ 组合式综合（跨领域知识重组）难以归因到具体机制；④ 人类实验环节成为吞吐瓶颈。[推测]
- **树定位**：milestone task = **端到端假设生成 + 湿实验闭环**；pipeline = **专用科研 agent 编排（Robin）**；novelty = **1 类（新 task：半自主发现闭环）/ 2 类（多智能体 pipeline）**。⚠️ 组内把他标成 "Emerald Cloud Lab 系商业系统"是**错误**的：Robin 是 FutureHouse（现 Edison Scientific）的 Nature 论文系统，与 Emerald Cloud Lab 无关。
- **challenge→insight**：C: 文献、假设、实验、分析各自为政。→ I: 用专用 agent + 上层编排把四步串成闭环，并让湿实验数据回流改写候选。C: AI 容易提"看似新"的假设。→ I: 用 Owl 类 agent 先做新颖性核查，再进入实验规划。

## C6. Operating Advanced Scientific Instruments with AI Agents That Learn on the Job

- **元信息**：Aikaterini Vriza、Michael H. Prince、Tao Zhou、Henry Chan、Mathew J. Cherukara（Argonne National Laboratory）｜出处 **npj Computational Materials** 12:160（2026；DOI: 10.1038/s41524-026-02005-0）；arXiv 2025-08｜年份 2025/2026｜**核验状态：已核验**（期刊引用 + arXiv/Aminer 摘要）[原文]
- **研究动机**：先进科学装置（X 射线光源、自驱动实验室）持续演化，运维复杂度高；需要"边干边学"的 agent 来降低使用门槛、提升可复现性与人机交互。[原文]
- **研究挑战**：① 新 workflow 不断出现，预训练 agent 无法覆盖；② 装置操作有安全与可复现要求；③ 人类需在环（human-in-the-loop）。[原文]
- **技术贡献**：提出 human-in-the-loop 的 agent 管线，面向 **X 射线纳米探针光束线**与**自主机器人材料站**；用 LLM 编排仪器操作与表征流程，并从运行经验中积累可复用知识（"learn on the job"）。[原文]
- **讨论**：[推测] 与 C3 的 X-ray scientist 是同一路线（仪器 agent）的不同实现：C3 强调 sim-to-real 自主对准，C6 强调持续学习与人机协同。局限是任务覆盖与"学到的东西"如何表示/迁移未明。
- **树定位**：milestone task = **仪器操作 agent**；pipeline = **HITL + 经验积累**；novelty = **2 类（pipeline）/ 3 类（学习模块）**。
- **challenge→insight**：C: 装置 workflow 持续变化。→ I: 让 agent 在人类监督下从每次运行中学习并复用。

## 本批小结（用于文献树）

| 工作 | novelty | milestone task | pipeline | 核验 |
|---|---|---|---|---|
| SciToolAgent | 2 类(+1) | 多工具科研编排 | KG-RAG 工具链 + 安全审查 | 已核验 |
| BioDiscoveryAgent | 1 类(+2) | 闭环基因扰动实验设计 | LLM+工具+多轮实验选择 | 已核验 |
| AI X-ray Scientist | 1 类(+2) | 真实仪器自主实验 | 虚拟装置→MCP→真机 | 已核验 |
| AutoLabs | 2 类 | 自主化学实验闭环 | 多智能体 + self-correction | 已核验 |
| Robin | 1 类(+2) | 端到端假设+湿实验闭环 | 专用 agent 编排 | 已核验 |
| AI agents learn on the job | 2 类 | 仪器操作 agent | HITL + 经验学习 | 已核验 |
| MatBrain/EmbodiedAct/ERA | — | — | — | 未找到 |

**这一层的判断**：
1. **已解决的是"接口与编排"**：MCP/工具图谱让 agent 能调用几百个工具（SciToolAgent、X-ray Scientist）。
2. **没有被解决的是"实验语义"**：agent 仍不会判断"这个实验值不值得做/失败意味着什么"；真实湿实验的闭环仍靠人类（Robin）或专用硬件（AutoLabs）。
3. **最值得做的空白**：① **sim2real 的实验策略迁移**（虚拟实验到真机，C3 只做了对准）；② **失败实验的归因与负结果复用**；③ **跨装置/跨机构的工具与协议标准**（MCP 化了，但语义不统一）。
