## A1. SciNet: Evaluating AI Agents in Relation-Aware Scientific Literature Retrieval

- **元信息**：作者 Chenyang Shao、Fengli Xu、Yong Li 等（清华大学电子系 / BNRist / 中关村学院；完整作者列表以 arXiv 页面为准）｜出处 **ICML 2026**（Poster；arXiv:2601.03260）｜年份 2026｜代码/数据：待查（论文主页未在检索结果中确认）｜**核验状态：已核验**（ICML 2026 Poster Session 8 页面 + arXiv HTML v2）[原文]
- **研究动机**：科研检索 agent（Deep Research 一类）已广泛用于文献调研，但主流检索仍靠关键词或 embedding 相似度，只能捕捉"内容像不像"，无法理解论文之间的关系网络——哪些工作互相印证、哪些结论冲突、某条技术路线如何演化。结果是知识结构碎片化、引用情感被误读、无法建模"集体科学进展"。[原文]
- **研究挑战**：① 关系型 ground truth 难以构造：需要跨论文的引用语境、情感、路径标注，而不是单篇相关性；② 规模大：需要覆盖多学科、数亿级论文的元数据库；③ 现有 benchmark 只考"找没找到相关论文"，不考"关系判断对不对"，因此 agent 的关系推理能力从未被系统测量。[原文+推测]
- **技术贡献**：提出 SciNet，首个面向检索 agent 的 **relation-aware 科学网络数据集**：基于 **2.69 亿篇论文、7 个学科**的元数据库，设计 **8,940 个任务**，系统覆盖三层关系理解——(1) 自我中心关系（论文的新颖性/颠覆性，非典型知识组合）；(2) 成对关系（引用情感：支持/批评/中立，共提及）；(3) 路径关系（从基础概念到最新方法的思想演化轨迹）。在此之上评测现有检索 agent，暴露其在关系判断上的系统性缺陷。[原文]
- **讨论**：
  - **是否有效**：作为"测量工具"是有效的——它第一次把"关系感知"拆成三层可评测任务，且规模足以覆盖学科差异。但它证明的是"现有 agent 关系推理差"，并没有提出解决关系推理的方法。[原文+推测]
  - **还能怎么解决**：把 citation graph / 引用语境作为一等检索对象（graph-native retrieval），让 agent 在图上做多跳证据聚合；用"关系类型预测"作为训练信号做 RL；评测端增加下游任务（如冲突证据汇总、路线图生成）验证关系能力的迁移价值。[推测]
  - **不足**：① 元数据库构建会继承元数据噪声与引用覆盖偏差（不同学科引用规范差异大）；② 8,940 任务相对 2.69 亿论文仍是稀疏采样，任务构造规则可能偏向可自动判定的关系；③ "路径关系"的 ground truth 多半来自历史引用链，存在后见之明（ hindsight）偏差；④ 未验证关系检索能力是否真的提升科研产出。[推测]
- **树定位**：milestone task = **关系感知文献检索评测**；pipeline/representation = **SciNet 三层关系任务 + 大规模元数据库**；novelty 类别 = **1 类（提出新的里程碑评测 task）**，并附带新的数据表示（citation-relation 三层标注）。
- **challenge→insight**：
  - C: 检索 agent 只会"语义相似"，不会判断支持/冲突/演化关系。→ I: 把关系拆成 ego / pairwise / path 三层，分别构造可自动判定的任务，让"关系"变成可测量的对象。
  - C: 关系标注无法人工全量完成。→ I: 以 2.69 亿论文元数据库为底座程序化采样 + 规则构造任务。[推测]

> ⚠️ 与组内初稿的差异：组内写"1800 万论文关系图"，ICML 2026 官方摘要写的是 **2.69 亿篇论文的元数据库 + 8,940 个任务**。汇报时建议以官方数字为准。另：组内把它放在 T1 是合理的，但它的贡献本质是 **benchmark / measurement**，不是 retrieval 方法。

## A2. OpenScholar: Synthesizing Scientific Literature with Retrieval-augmented LMs

- **元信息**：作者 Akari Asai、Jacqueline He、Rulin Shao、Weijia Shi、Amanpreet Singh、Joseph Chee Chang 等（Allen Institute for AI / University of Washington）｜出处 arXiv:2411.14199（2024-11）｜年份 2024｜代码/数据：OpenScholar 开源（ScholarDB / ScholarQABench 随论文发布）｜**核验状态：已核验**（arXiv API 元数据 + 摘要）[原文]
- **研究动机**：通用 LLM 做文献综述时会产生虚假引用，而科研写作要求"每句话都能落到真实论文上"。需要一个开源的、面向 4500 万篇开放获取论文的检索增强模型 + 数据管线，作为闭源 Deep Research 的开放基线。[原文+组内补充]
- **研究挑战**：① 开放获取论文规模巨大、格式异构，检索与段落级证据对齐困难；② 文献综合任务没有唯一答案，既要覆盖全面又要引用准确；③ 训练数据稀缺，缺少"问题—证据—带引用综述"的高质量样本。[原文+推测]
- **技术贡献**：构建 OpenScholar：检索器 + 生成器 + **self-feedback 推理循环**（模型自查引用是否被证据支持并迭代）；配套 **ScholarDB**（约 4500 万篇开放获取论文）与 **ScholarQABench**（多领域文献综合评测）；提出用 GPT-4o 生成训练数据、以引用正确性为过滤的管线。论文报告：在 ScholarQABench 上比 GPT-4o 高约 5%，引用准确率与人类专家相当（GPT-4o 有 78–90% 的引用幻觉）。[原文]
- **讨论**：
  - **是否有效**：在"开放可获得文献 + 引用可验证"这个设定下是当前最强开源基线之一；但"citation accuracy 与人类专家相当"是指引用存在且支持陈述，不等于综述的洞察深度相当。[原文+推测]
  - **还能怎么解决**：把引用验证从"事后 self-feedback"前移到检索阶段的 evidence pack 构造；引入全文图表与 supplementary 证据；对综述做 claim-level entailment 校验，而不是 citation-level 存在性校验。[推测]
  - **不足**：① 只覆盖开放获取论文，付费墙后的关键工作缺失，领域偏差明显；② 以 GPT-4o 合成训练数据，会继承其写作风格与知识盲区；③ 评测偏"引用正确/覆盖"，对"是否发现争议、是否指出空白"覆盖不足；④ 4500 万篇的检索延迟与成本对交互式使用不友好。[推测]
- **树定位**：milestone task = **可验证引用的文献综合**；pipeline/representation = **检索增强 + 自反馈引用校验（OpenScholar pipeline）**；novelty 类别 = **2 类（提出新的 pipeline 与开放数据/评测表示）**。
- **challenge→insight**：
  - C: LLM 综述的引用幻觉。→ I: 先生成、再逐条用检索证据自检并重写（self-feedback），把"引用"当作可验证约束而非文风装饰。
  - C: 缺训练数据。→ I: 用强模型合成 + 引用正确性过滤，构造大规模文献综合训练集。

## A3. PaperQA2（论文：Language agents achieve superhuman synthesis of scientific knowledge）

- **元信息**：作者 Michael D. Skarlinski、Sam Cox、Jon M. Laurent、James D. Braza、Michaela Hinks、Michael J. Hammerling 等（FutureHouse）｜出处 arXiv:2409.13740（2024-09）｜年份 2024｜代码：paperqa2 开源包｜**核验状态：已核验**（arXiv API + HTML 全文摘要）[原文]
- **研究动机**：科学知识综合（literature search、summary、contradiction detection）是科研的基础劳动，但 LLM 在科学文献上幻觉严重。作者要回答：一个"够严谨"的语言 agent 能否在真实文献任务上超过人类博士级专家？[原文]
- **研究挑战**：① 检索到的段落未必支持结论，需要逐 claim 的证据绑定；② 科学问题常需跨多篇论文聚合，单轮 RAG 不够；③ 缺少能与人类对比的、需要真实检索的评测集。[原文+推测]
- **技术贡献**：PaperQA2 = 多步 agentic RAG：查询规划 → 全文/摘要检索 → 段落重排 → 证据聚合 → 带引用作答，并支持工具调用与迭代；构造 **LitQA2**（248 道必须检索文献才能答的多选题）与 **LitQA2 人类对比协议**；在 Wikipedia 级科学条目写作上比现有 Wikipedia 文章更准确；论文声称在部分任务上达到"superhuman"。[原文]
- **讨论**：
  - **是否有效**："超人类"结论主要建立在 LitQA2 选择题与 Wikipedia 事实准确性上，属于**受限任务上的事实综合**；对"提出新联系/判断重要性"没有证明。[原文+推测]
  - **还能怎么解决**：把 claim-level 证据图作为中间表示，允许 agent 显式记录"支持/反驳/不确定"；引入反驳检索（contradiction search）作为一等动作；用专家 rubric 评"综合质量"而非仅事实正确。[推测]
  - **不足**：① 单次查询成本高（多轮检索 + 重排 + 长上下文）；② 依赖全文可获取；③ 评测以选择题为主，存在"选项可被排除"的捷径；④ "superhuman"是作者自报指标，尚未被独立复现。[推测]
- **树定位**：milestone task = **高精度科研文献问答/综合**；pipeline/representation = **agentic RAG（检索—重排—证据聚合—引用）**；novelty 类别 = **2 类（新 pipeline）+ 1 类（LitQA2 评测 task）**。
- **challenge→insight**：
  - C: 单轮 RAG 的证据不足且不可核查。→ I: 把检索拆成多步 agent 工具调用，并把每个结论绑定到具体段落。
  - C: 无法证明"超过人类"。→ I: 设计需要真实检索的 LitQA2 + 人类对照协议，把"综合能力"操作化。

## A4. SciArena: An Open Evaluation Platform for Non-Verifiable Scientific Literature-Grounded Tasks

- **元信息**：Yilun Zhao、Kaiyan Zhang、Tiansheng Hu、Sihong Wu、Ronan Le Bras、Charles McGrady、Taira Anderson、Jonathan Bragg、Joseph Chee Chang、Jesse Dodge 等（AI2 等）｜出处 arXiv:2507.01001（2025-07）｜年份 2025｜平台：sciarena.org（开源）｜**核验状态：已核验**（arXiv 元数据；完整 18 人作者列表见 `00-元数据核验表.md`）[原文]
- **研究动机**：大量科研文献任务是开放式的（写综述、比较方法、解释证据），没有唯一答案，自动指标失效。需要一种能反映真实科研用户偏好的评测方式，而不是又一个静态 benchmark。[原文]
- **研究挑战**：① 开放式任务难以自动判分；② 专家标注昂贵且难以规模化；③ 模型排名需要控制问题分布、投票者质量与自选择偏差。[原文+推测]
- **技术贡献**：SciArena 平台：研究者提交真实文献问题 → 系统用多阶段检索管线（改编自 AI2 Scholar QA）取证据 → 两个匿名模型并排作答 → 用户投票 → Elo 排行榜；已支持 23 个开源/闭源模型、收集 13,000+ 票；发布 **SciArena-Eval** 元评测集，用"模型判断人类偏好"的准确率来检验 LLM-as-judge 是否可靠。[原文]
- **讨论**：
  - **是否有效**：解决了"开放式科研任务没有排行榜"的问题，且元评测揭示了 LLM judge 与人类偏好仍有明显差距——这本身是重要负面结果。[原文]
  - **还能怎么解决**：引入任务分层（事实核查/综合/批判）与专家资格校验；用成对投票训练奖励模型，再对 judge 做校准；把"引用正确性"作为投票界面的一等信息，降低风格偏差。[推测]
  - **不足**：① 投票者以 AI/NLP 研究者为主，学科与任务分布偏 CS；② 偏好 ≠ 正确，用户可能偏好更长、更自信的回答；③ 13,000 票对 23 个模型 × 多学科仍稀疏；④ 平台式评测难以复现历史快照。[推测]
- **树定位**：milestone task = **开放式科研任务的人类偏好评测**；pipeline/representation = **Arena + Elo + 元评测（SciArena-Eval）**；novelty 类别 = **1 类（新评测 task / 平台）**。
- **challenge→insight**：
  - C: 开放式科研问答无法自动判分。→ I: 借 Chatbot Arena 的成对匿名投票 + Elo，把"质量"转成相对偏好。
  - C: LLM judge 是否可信未知。→ I: 用人类投票做元评测，量化 judge 与人的一致性。

## A5. SAGE: One Reflection Is Not Enough: Self-Correcting Autonomous Research via Multi-Hypothesis Failure Attribution

- **元信息**：**未找到**。本轮检索（Google/Bing 关键词：标题全名、SAGE self-correcting multi-hypothesis failure attribution、arXiv 2026）只命中另一篇同名不同作的 **SAGE: Benchmarking and Improving Retrieval for Deep Research Agents**（2026-02，科学文献检索 benchmark，1,200 查询 / 20 万篇语料），与本条描述（多假设失败归因、把修复路由到对应环节）不一致。｜**核验状态：未找到（疑似组内工作/预印本尚未公开，或名称记忆有误）** [未找到]
- **可确认的信息（来自组内条目）**：把单次自我反思重构为**多假设失败归因**：失败后同时生成多个候选原因、对关键假设逐一验证、再把修复路由到对应环节。[组内原文]
- **为什么值得关注（若条目属实）**：[推测] 它瞄准的是当前 self-reflection 的核心缺陷——单条反思容易"编一个说得通的原因"就改，缺乏对失败原因的后验区分。多假设 + 逐一验证本质上是把**故障诊断（fault diagnosis）**引入 agent 自改进，这与 L3 的"经验→技能沉淀"和 T6 的"证伪"都能连起来。
- **讨论（基于描述的批判）**：[推测] ① 多假设归因的成本随假设数线性上升，需要看它如何剪枝；② "验证关键假设"若仍在同一环境里做，可能共享同一错误前提；③ 归因正确性由谁判分？若用 LLM judge，存在自我确证风险；④ 需要与简单 baseline（多试几次 + 选最好）区分开，否则收益可能来自 test-time compute 而非归因机制。
- **树定位**：milestone task = **科研 agent 失败归因与自修复**（若成立，是新的评测/方法 task）；pipeline = 多假设失败归因 → 验证 → 路由修复；novelty 类别 = **1 类（新 task）/ 2 类（新 pipeline）**，待原文确认。
- **challenge→insight**：C: 单次反思只产生一个"看似合理"的失败解释，修复容易打错靶。→ I: 同时提出多个失败假设，用可观察证据逐一排除，再把修复动作路由到真正出错的环节。
- **待办**：向组内要 arXiv 号/PDF；若确认不存在，汇报时应从"已发表工作"中移除，避免被质疑。

## 本批小结（用于文献树）

| 工作 | novelty | milestone task | pipeline / representation | 核验 |
|---|---|---|---|---|
| SciNet | 1 类 | 关系感知文献检索评测 | 三层关系任务 + 2.69 亿论文元数据库 | 已核验 |
| OpenScholar | 2 类 | 可验证引用的文献综合 | 检索增强 + 自反馈引用校验 + ScholarDB | 已核验 |
| PaperQA2 | 2 类(+1) | 高精度科研文献问答/综合 | agentic RAG + LitQA2 | 已核验 |
| SciArena | 1 类 | 开放式科研任务人类偏好评测 | Arena/Elo + SciArena-Eval | 已核验 |
| SAGE (MHFA) | 待定 | 失败归因与自修复 | 多假设归因→验证→路由 | 未找到 |

**这一层真正的空白（本批判断）**：
1. **关系推理没有被"解决"，只被"测量"**：SciNet 之后，仍缺一个 graph-native retrieval agent，能把支持/冲突/演化关系作为检索与推理的一等对象。
2. **证据包（evidence pack）与 provenance 仍是工程拼接**：OpenScholar / PaperQA2 都在做 claim→段落绑定，但没有统一本体，跨工具不可复用（对应 L3-T2 的核心问题）。
3. **开放式任务的 judge 不可靠**：SciArena-Eval 已量化这一点，但"如何校准科研 judge"仍无标准协议。
