# 二维模型确认：方法注册表就是"研究阶段 × 研究方法"手绘图的实现——附自改进的三层定位

> 状态基线：2026-11-21。承接 158（ML 迭代实验方法）与 2026-11-17 讨论（"科研工作两个维度：研究阶段 × 研究方法；交叉 = 阶段性任务，有相应方法论；具体任务在方法论约束下开展；先聚焦 empirical software engineering"）与研讨纪要待办 #2。
> 本文新增前端**任务卡矩阵视图**（数据已存在：stage_tasks）；完成对"自改进不只改进 skill，还要改进整个科研流程"的三层定位。

---

## 0. 一句话结论

讨论组里画的二维模型（研究阶段 × 研究方法，交叉点 = 方法论约束下的阶段性任务）——**方法注册表的 `stages × methods × stage_tasks` 就是它的数据实现**，早已存在，只是没有按这张图的形态渲染。本轮方法模型页矩阵新增**任务卡视图**：交叉格直接显示方法论约束的任务文本（而非点阵）。至此导师手绘图被完整前端化：行 = 治理槽位（不变），列 = 方法（数据），格 = 方法论约束下的任务卡。自改进的层级也由此清晰：改 skill = 微观；**修订矩阵交叉点 = 流程级**（须走组合提案租约，156 §4）；改元模型（要素/端口/门）= 治理级（SPEC + 人签）。

## 1. 二维模型 ↔ 注册表的逐格对应（验证）

讨论组截图的要点 → 系统数据：
- "两个维度：研究阶段 × 研究方法" → registry.stages（10 槽位）× registry.methods（10 方法）；
- "交叉就变成具体的阶段性任务，有相应的方法论" → method.stage_tasks[slot]（任务卡）+ protocol_fields/checks（方法论约束）+ guidelines（指导性论文：Kitchenham/Wohlin/PRISMA/Runeson & Höst…）；
- "先主要聚焦 empirical software engineering" → 现有 10 方法全部属于实证软件工程谱系（Easterbrook 2008 策略分类）；
- "不同的研究方法都有指导性的论文和书籍" → 每方法 guidelines 块（逐条 citation）。

**矩阵任务卡视图实测**（静态构建）：SLR 行 = "先写检索协议再检索…"/"按 PRISMA 与 Kitchenham"；挖掘行 = "时间切分必须先于建模；去重策略与标签来源写进预注册"；受控实验行 = "预注册：随机化、区组、主指标、分析计划、停止规则"——交叉格文本逐字来自注册表 stage_tasks，正是手绘图要求的方法论约束下的阶段性任务。

## 2. 自改进的三层定位（回应"自改进不只改进 skill"）

| 层级 | 改什么 | 治理 | 系统现状 |
|---|---|---|---|
| L1 微观 | skill/提示词（单槽位内的执行） | skill 注册 + advisory | 已有（skills 模块） |
| **L2 流程级** | **矩阵交叉点的任务卡修订、方法列增改、组合接线调整** | 组合提案租约（154 §4 形式定义）：端口校验 + 治理门 + 历史回放 + 人签 | **roadmap（本轮把矩阵上屏，使 L2 的对象可见）** |
| L3 治理级 | 元模型本身（要素/端口/门语义/证据三元组） | SPEC + 人签 + 治理不变式回归 | 元模型层 roadmap（152 G1/G2/G3） |

关键认知（回应"自进化系统是否需要固定架构"）：L2 的存在证明**架构不是固定的，但也不是无界的**——它是一个"可修订的数据矩阵 + 不变的治理行/列语义"。自改进 = 在租约下修订矩阵内容（L2），而矩阵的行列语义（L3）与用户面固定。

## 3. 设计主张（可证伪）

1. 导师手绘的二维模型与注册表 stages×methods×stage_tasks **结构同构**——本轮只是补渲染；若发现某方法论约束无法放进交叉格（如跨阶段的伦理连续性），说明词表/槽位需要扩展（可证伪）；
2. 自改进的层级必须显式建模（L1/L2/L3），否则"改 skill"会冒充"改进流程"——这是 139"平台自身双标"反思的延续；
3. 交叉点任务卡使"为何当前流程顺序如此"的答案从要素图（151）下沉到**方法论出处**（每格可引 Kitchenham/Wohlin 等文献）。
