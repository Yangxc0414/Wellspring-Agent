## 0. 这一轮为什么还要再审视

131 的结论是「设置页、按钮走查、种子自洽、四投影流程图保持现状」。这次用户明确点名了三个 131 没系统覆盖的角度——**demo 首页、左侧栏历史对话、流程图要改进**、证据链要再想、各 HTML 子页按钮逻辑。我因此换了方法：不再读代码判断，而是**真实浏览器逐页点击 + DOM 探测 + 截图**，按「结构 / 层级 / 流程 / 按钮文案 / 状态反馈 / 空错加载」六个维度过。

审计分四路并行（首页+历史、流程图+证据链、HTML 子页、发布树同步），下面只列**真实发现并已修**的问题。

## 1. 首页（WelcomeHome）

### 1.1 产品定位沉在装饰里（严重，已修）
`h1` 曾是时段问候语（"早上好，今天从哪一步开始"），产品名 `WELLSRING AGENT` 是 `aria-hidden` 的水印装饰。视觉最高层级没回答"这是什么"，读屏用户完全看不到产品名。
修：加 `.eyebrow`「WELLSPRING AGENT · {greeting}」（复用已有但未用的 CSS），`h1` 改为「科研智能体工作台」。问候语降级为 eyebrow 一部分，既不丢温度又立住定位。

### 1.2 三个示例是半句（严重，已修）
"…证据缺口：" / "…seeds：" / "主题是：" 都以冒号结尾，而提示写"填入输入框再按发送"——照做就发出半句。
修：补全为完整问题（如"…主题是：界面钝化与湿热稳定性"），填入即可发送。

### 1.3 "点击填入"只在 hover（中等，已修）
行为说明全在 `title`，触屏/不悬停用户会把示例 chip 当成"点了就执行"。
修：加可见提示行"点选示例会填入下方输入框，确认后再发送"，每个 chip 加可见「填入」小标签。

## 2. 左侧栏历史对话

### 2.1 阻塞状态被演示标签吞掉（严重，已修）
`taskStatus()` 先判 `DEMO_LABELS` 再判 `blocked`，导致 `full-chain-demo`（status=blocked）只显示"全流程演示"，而右侧面板明确写 `gate pending` / `HUMAN GATE`。演示者讲"停在人签门"时两侧直接冲突。
修：demo 标签若遇 blocked 且标签不含"待签"，追加"· 待签"。实测侧栏显示「全流程演示 · 待签」。

## 3. 流程图与证据链

### 3.1 FlowDemo 展开永远慢一步（功能 bug，已修）
推进按钮 `setStep(s=>s+1)` 用函数式更新，但 `setOpen(Math.min(step,...))` 用的是闭包里的旧 `step`——展开的是刚完成的上一阶段，演示者指不到当前阶段。
修：先算 `next = step + 1`，两处都用 `next`。实测推进后从 S1 正确展开到 S2–S3。

### 3.2 人工门三重标记 + 双色（中等，已修）
节点图标"人" + 珊瑚 G-code 徽标 + 琥珀"人工"徽标，一个概念三种提示两种颜色；且所有 human 阶段都带 gate 字段，"人工"徽标纯冗余。
修：删琥珀"人工"徽标，保留图标+门徽标。实测 `.flow-stage-human` 归零。

### 3.3 证据链三套命名、断行修复没解决的顺序问题（严重，已修）
可视节点是「来源/片段/断言/证据/闭合」，同页说明是「来源/片段/运行记录/证据制品/断言」，FlowDemo 的 CHAIN 又是第三套。最要命的是顺序：视觉上"断言"排在"证据"之前、"闭合"收尾，说明里却是"证据制品"在"断言"之前、以"断言"收尾——"证据怎么走"一眼读不通。
修：统一为真实工作流六段「来源→片段→运行记录→证据制品→断言→闭合」，可视节点与文字说明完全一致；加三态图例（已就绪/待人工/未产出）+ 连线方向箭头（左到右=证据依赖）。

### 3.4 四投影流程图（检查后不改，理由见 §5）
131 判定保持现状。这轮从"读者能否读懂"再审，确有可读性问题（读图顺序③→①→②→④与版式相反、颜色语义跨图漂移、①把未实现的反馈环画得像已实现）。但四投影在 `site/index.html` 静态页、按设计是**设计意图图**而非操作图，改动需重画四个 SVG 并同步读图文案，属独立设计任务；本轮不夹带，记入下一步。

## 4. HTML demo 子页

### 4.1 legibility guide 从未挂载（隐藏 bug，已修）
`site/assets/demo-legibility.js` 的 `mount()` 读 `document.body.getAttribute("data-dl-page")`，但所有 demo 页的标记在 `<main>` 上。结果：**五个子页的阅读说明卡从来没显示过**（`DemoLegibility` 甚至未导出到正确路径的页面）。
修：从 `main` 读属性，回退 body。实测所有子页 guide 出现，frontier 页从"none"变为正常挂载。

### 4.2 SIM 卡与真实回放页正面冲突（严重，已修）
脚本硬编码"所有数值是演示数据 / SIM"，但 demo/index、run/、frontier/ 都明确写"真实运行回放 / 非 SIM / fixture_mode: false"。读者看到自相矛盾的两句话。
修：`isRealReplay()` 检测页面自身声明（`fixture_mode:false` 或"非 SIM"），真实回放页显示"真实运行回放 · 只读"卡片与对应文案，纯 SIM 页（ese-ms-03）仍显示 SIM。

### 4.3 frontier 页所有相对路径少一级（严重，已修）
frontier 在 `demo/frontier/`，却引用 `../assets/demo-legibility.{js,css}` → 解析到不存在的 `site/demo/assets/`；两个 `/app/` 入口同样少一级。这是 4.1 里 frontier 特殊的直接原因。
修：三类路径改为 `../../`。实测 frontier 的 guide 与工作台入口均可达。

### 4.4 ese-ms-03 边界自相矛盾 + 本机路径（严重，已修）
第 0 节表格明写"EA 已完成"，边界却写"no Claim/EA/signature"；命令块还暴露 `D:/Program Files/Python38/python.exe`。
修：生成脚本在 boundary 后补中文澄清——"no Claim/EA/signature 指本页只读回放不新建证据，与表格里实际产物状态不矛盾"；解释器路径改为通用 `python`。同步脚本避免重新生成回退。

### 4.5 标题口径与 CLI 复制正则（中等，已修）
四个子页 title 格式不一（旧名/无品牌/两页同名），统一为「页名 · Research Agent」并同步生成脚本。CLI 复制按钮正则只认 `python -m`，认不出引号包裹的解释器路径，已放宽为 `-m\s+research_agent`。

## 5. 检查后不改的（附理由）

- **四投影流程图的可读性**：属设计意图图，改它要重画四个 SVG，独立任务。
- **历史对话的时间分组 / N/9 进度条**：侧栏当前按角色标签分组（demo 叙事需要），加时间分组会打散"一个项目的连续过程"；进度 hover 已有，升为常驻会挤占窄侧栏。记为下一步。
- **"新建任务"一个标签两种动作**：欢迎页/会话页语义不同但 title 已说明，改动收益低。
- **ESE 五产物 vs 证据链六段同名**：前者是 ESE 血缘，后者是通用证据链，语境不同，保留。
