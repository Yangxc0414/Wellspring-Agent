## 1. 发现的问题与处置

### 1.1 源副本违规：demo 页改动只写进了 site 副本（严重，已修）

`scripts/repo_hygiene.py` 把 `demo/index.html → site/demo/index.html` 列为必须逐字一致的生成对；上一轮的状态色徽章、sp-top 导航与中文优先文案**只改进了 `site/demo/index.html`**，`demo/index.html`（源）还是旧版，hygiene 直接 `BLOCK site_copy_drift`。

处置：确认 `scripts/build-site.mjs` 对 demo 是纯 `copyTree`（无转换）后，把副本内容回写为源 `demo/index.html`，重跑 `node scripts/build-site.mjs`，两侧逐字一致，hygiene 恢复 ok。

教训写明：**改生成副本不是修复，是把 drift 固化**；方向永远是「改源 → 重跑生成脚本」。

### 1.2 子页标题两种语序并存 + 页名与可见标题不一致（中等，已修）

全站 9 个页面标题存在两套语序：`页名 · Research Agent`（运行回放/接入/自进化接缝/文档/404，5 个）与 `Research Agent · 页名`（创新点演示/模型接入/Local Runtime，3 个）；其中「模型接入」页可见 h1 是中文「模型接入」，标题却是英文 "Model Gateway"。

处置（统一为「页名 · Research Agent」，与多数派及 130 轮刚改的运行回放一致）：
- 创新点演示：`Research Agent · 创新点演示` → `创新点演示 · Research Agent`（纯语序）；
- 模型接入：`Research Agent · Model Gateway` → `模型接入 · Research Agent`（语序 + 页名与可见 h1 对齐）；
- Local Runtime：`Research Agent · Local Runtime` → `Local Runtime · Research Agent`（纯语序；页面可见品牌是英文 "LOCAL RUNTIME"，不强行中文化）。

实测：9 个页面标题逐一回读，全部归入同一语序；工作台标题为 `Wellspring Agent · 工作台`，与 demo 站「Research Agent」品牌按两产品定位分开。

### 1.3 工作台内部品牌残留（中等，已修）

`apps/web/index.html` 与 TopBar 已是 Wellspring Agent，但组件内部仍有 6 处 "Research Agent"：folderStorage 导出元数据、Composer aria-label、Conversation 发言人名、WelcomeHome 输入占位、SettingsPage 品牌行、SettingsSections 描述。

处置：6 处统一替换为 "Wellspring Agent"（`SettingsSections` 的 "Research Agent Workspace · 证据…" 简化为 "Wellspring Agent · 证据…"）。`folderStorage` 的 `app` 字段是导出元数据里的展示标签（判别靠 `schema_version`），无读取方依赖，改名无兼容影响；web 单测无品牌断言，不破锚。

实测：`grep "Research Agent" apps/web/src` 归零；`npm run build:site` 重建后浏览器确认 TopBar、对话发言人名、PROJECTS 空态全部显示新品牌；旧快照里的历史 META 标签不受影响（只写不读）。

### 1.4 统计数字「1500+」模糊值改为可复算精确值（小，已修）

主页统计区 `1500+ 自动测试用例` 改为 `1695`。核实方法：`unittest.TestLoader().discover('tests').countTestCases()` = **1695**（注意 `grep "def test_"` 会数到 1697——多出 2 个同名帮助函数，不能作为计数来源）。同页「34 模块 SPEC / 46 MCP 工具 / 4 人工门」逐一与 AGENTS.md 模块表、`tools/list`、门禁清单核对无漂移。

## 6. 续篇三：按钮级点击走查——原生 confirm 收口与卸载隐藏 bug（131d 补交）

按「各个按钮都可以进行点击截图等反思改进」继续做按钮级走查（真实浏览器逐项点击，非静态代码审读）。

### 6.1 四处置 destructive 动作的原生 `window.confirm` 统一为自研 ConfirmDialog（已修）

侧栏的任务/工作区删除早已有 `.confirm-layer/.confirm-card` 卡片（eyebrow + 标题 + danger 按钮），但四处仍在使用原生 `window.confirm()`：设置·数据与备份的「重置为示例」、命令面板的两个「重置示例」入口、子智能体分区的行内「删除」。原生 confirm 在自研 UI 里跳出 OS 对话框，风格断裂；无参调用还会显示 "undefined"。

处置：新增 `components/ConfirmDialog.tsx`（复用侧栏同款 `.confirm-layer/.confirm-card` 形状，portal 到 body，`role=alertdialog` + 点击遮罩关闭 + 取消/danger 确认两键），四处全部接入，`grep window.confirm` 在 src 归零（仅剩该文件注释里的一处说明性提及）。

### 6.2 走查抓出的隐藏 bug：命令面板重置确认卡从未渲染过（已修）

浏览器实测点击面板「重置示例」后**确认卡不出现**——根因不是文案或样式，是挂载结构：`App.tsx` 里 `{ui.paletteOpen && <CommandPalette />}` 条件挂载，而 `execute()` 的顺序是「先关面板 → 再 run 动作」，`setConfirmReset(true)` 触发时组件已随 `paletteOpen=false` 卸载，ConfirmDialog 随组件一起消失。设置页与子智能体分区不受影响（宿主页面持续挂载），只有面板这一处踩中。

修法（最小化）：`App.tsx` 改为无条件渲染 `<CommandPalette />`；组件内订阅 `paletteOpen`，用 `{paletteOpen && …}` 只门控 `.palette-layer`，ConfirmDialog 留在门控外（它自身 portal 到 body）；补一个「面板关闭即清空 query/index」的 effect，保住改动前每次打开都是全新会话的语义。
