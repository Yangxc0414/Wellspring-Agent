# 研究方法与研究流程的变与不变——把"凭什么这么建模"落到证据的性质上

> 状态基线：2026-11-21。触发：研讨纪要 + 张老师微信意见（"科研工作两个维度：研究阶段 × 研究方法；两者交叉成阶段性任务，在方法论约束下开展；先聚焦 empirical software engineering；每种方法都有指导性论文书籍"）。
> 承接 152（研究本质第一性推导）、154（端口模型）、162（组合计划）、163（控制表）、165（执行层检验）。本文把"变与不变"的定义权从界面挪回研究方法论，并给出对现有注册表的改造建议。

---

## 0. 一句话结论

**变与不变的切分点不在"界面 vs 逻辑"，而在"可核查性是否被保留"。**

不变的是一条规则：任何主张都必须有可核查的证据，并且必须声明这个证据能支持到什么程度（效力）。可变的是证据长什么样、效力叫什么名、按什么顺序收集——**而这些"变"本身不是任意的，它们由方法的效力类型决定**。

这就是老师要的"客观逻辑"：不是我拍脑袋说这个方法要这样走，而是文献已经写清了每种方法的效力类型，顺序是从效力类型推出来的。

## 1. 纪要真正在问什么

把纪要里反复出现的追问提炼成三个问题，它们其实是同一个问题的三层：

1. **"研究和工程开发、经验研究的本质区别是什么？"** ——这是在问建模的边界：哪些东西算研究、哪些不算。没有这条边界，"方法注册表"就只是个流程模板库。
2. **"为何当前流程顺序如此？"** ——这是在问顺序的合法性来源。如果顺序来自"我习惯了这么排"，那它就是经验；如果来自"证据何时可用"，它就是推导。
3. **"变与不变的抽象层级在哪？"** ——这是在问哪一层固定。答案不能是"界面固定、逻辑动态"这种产品话术，而必须是方法论层面的陈述。

我的回答：**三问都指向同一件事——证据的性质**。研究区别于工程的地方在于它产出的是"关于世界的主张 + 支持它的证据 + 这个证据的效力声明"；顺序由证据的依赖关系决定；不变的层级是"可核查性"这条治理语义。

---

## 2. 研究的本质：主张—证据—论证三元组，加一组负例

我把"研究"定义为一个三元组：

- **主张（Claim）**：一个可否证的陈述。可否证是硬条件——"这个系统很好"不是主张，"在 X 数据集上 Y 指标优于 Z"才是。
- **证据（Evidence）**：支撑主张的可核查材料。可核查 = 可固定（哈希/版本）、可复算（别人能重跑）、可定位（指回具体来源）。
- **论证效力（Validity）**：这个证据**能**支持主张到什么范围、**不能**支持到什么范围。效力不是附注，是主张的一部分——没有效力声明的主张是不完整的。

### 2.1 一组"不算研究"的对照（这是新加的）

老师反复区分"毕业设计 vs 毕业论文""研究 vs 工程 vs 经验"，我的注册表却没有负例。补上对照，"本质"才成立：

| 形态 | 缺什么 | 为什么不算（完整）研究 |
|---|---|---|
| 纯工程交付 | 无可否证主张 | 造出能用的东西 ≠ 主张了关于世界的事实 |
| 纯经验报告 | 无可核查证据 | "我觉得这样好"没有可复算的证据 |
| 只有 SOTA 数字 | 无效力声明 | 数字高不等于结论成立；需要说明在哪个范围、什么条件下成立 |
| 事后解释冒充预测 | 违反论证效力 | HARKing：把结果知情后的假设当成事前假设（Kerr 1998） |

**这张表就是注册表的准入条件**：一个方法若不能声明它的证据形态与效力类型，它就不该被注册为"研究方法"。这是可检验的边界，不是口号。

## 3. 变与不变的新切法

163 的控制表按"治理语义 / 方法数据 / 任务实例"三层切，那是架构视角。本文补一个**方法论视角**的切法，两者对应：

| | 不变（必须保留） | 可变（随方法） | 依据 |
|---|---|---|---|
| **可核查性** | 证据必须可固定 / 可复算 / 可定位 | — | 三元组的定义 |
| **效力声明** | 每个主张必须声明效力范围 | 效力**类型**随方法变 | Cook & Campbell 1979；Lincoln & Guba 1985 |
| **证据形态** | 必须能映射到三元组 | 文献 / 版本历史 / 应答集 / 随机对照测量 / 三角验证链 / 消融记录 | 各方法的指导性文献 |
| **阶段顺序** | 必须能被证据依赖解释 | 顺序本身可变 | 见 §4 |
| **交互外壳** | 用户侧界面稳定 | 面板内容随实例变 | 纪要"用户侧静态" |

关键：**"可变"不是"随便变"，而是"在不变的可核查性约束下变"。** 这就是为什么自进化可以改方法编排，却不能改"claim 必须有人签"——后者是尺子，前者是被量的东西。

## 4. 十种方法的本质差异矩阵

这是本文的核心。每一列都来自文献，不是经验（出处见 §7）：

| 方法 | 证据形态 | 首要效力 | 顺序的理由 | 不可支持（cannot_support 的实质） |
|---|---|---|---|---|
| **SLR** | 已发表文献 + 筛选流 | 可复现性（检索可重放）+ 筛选一致性 | 先定协议再检索，防选择性纳入 | 不做因果断言 |
| **受控实验** | 随机对照的测量 | **内部效度**（因果）+ 统计结论效度 | **假设必须先于数据**（防 HARKing）；随机化 + 控制 | 未控制的变量不构成因果 |
| **准实验** | 非随机的对照测量 | 内部效度（选择偏倚是首要威胁） | 先声明识别策略再看结果 | 无随机分配 → 因果更弱，需敏感性分析 |
| **基准评估** | 基准任务的得分 | 构造效度（基准是否测到宣称的能力）+ 污染控制 | 先声明防污染再跑分 | 高分 ≠ 真实能力（饱和/污染） |
| **仓库挖掘** | 版本历史快照 | **构造效度**（标签是否测到构念）+ 可复现 | 先冻结快照再统计，防数据漂移 | 启发式标签 ≠ 人工标注的构念 |
| **案例研究** | 三角验证的链式证据 | **可转移性**（非统计泛化） | **可先收资料再归纳假设**（分析性泛化） | 不能外推到总体 |
| **调查** | 应答数据集 | 构念效度 + 代表性 | 先预试再正式发放 | 未响应者偏差不可消除 |
| **DSR** | 产物 + 效用评估 | 效用（utility/quality/efficacy）+ 贡献类型 | **构建—评估是回路**，不是直线 | 未评估的效用不能宣称 |
| **行动研究** | 介入循环记录 | 循环完整性 + 研究者角色透明 | 诊断→行动→评估→反思的循环 | 角色不透明则证据不可信 |
| **ML 迭代实验** | 多种子 + 消融记录 | 判别力（消融能否区分贡献）+ 可复现 | 一次一因素；先最小可行再扩展 | 单点估计不可靠（Agarwal 2021） |

**这张表就是"客观逻辑"**：每种方法的差异都落在证据形态、效力类型、顺序理由三处，而这三处都有文献依据。注册表应该直接编码这三列，而不是只编码 fit_stages 和标签。

## 5. 顺序为什么是"证据依赖性"，不是习惯

老师追问"为何当前流程顺序如此"时，正确的回答不是"业界都这么做"，而是：**顺序由"证据何时可用、假设何时成立"决定**。四种典型：

1. **受控实验：假设必须先于数据。** 不是因为习惯，而是因为事后假设冒充事前假设会破坏效力（HARKing，Kerr 1998；预注册同时约束选择性分析与 p-hacking，Nosek et al. 2018）。所以 S2–S3（假设）必须在 S5（执行）之前。
2. **案例研究 / 扎根：假设可以在资料之后。** 它做的是分析性泛化（Runeson & Höst 2009），先收集资料再归纳类属是合法的；扎根理论甚至以"理论饱和"为停止规则（Glaser & Strauss 1967），收集与分析交错，**根本没有固定阶段数**。
3. **DSR：构建与评估是回路。** Hevner et al. 2004 要求"构建产物 + 严格评估效用"，贡献分三类（产物 / 设计基础 / 设计方法），不是单向流水线。
4. **SLR：协议先于检索。** Kitchenham & Charters 2007 要求"预先制定协议"（注意：这是方法文献里的 protocol，不等同于现代公共注册的 pre-registration）。

**结论：顺序差异 = 证据依赖差异。** 组合接线（confirmatory / exploratory）不是两种审美偏好，而是"假设是否必须先成立"的两种合法答案。

### 5.1 一个被忽略的维度：迭代与停止规则

当前组合是有限阶段列表，但**有些方法本质上是开放循环**：扎根理论以理论饱和停止、行动研究以循环完整性停止、DSR 以效用评估回路停止。这提示组合模型需要的不只是 wiring 顺序，还有**停止规则**（何时算走完）。目前的 wiring 无法表达"直到饱和为止"，这是一个真实缺口。

## 6. 对现有注册表的改造建议（SPEC 级，不本轮实现代码）

注册表 0.5 已有 fit_stages / 三维 / 标签 / 组合绑定 / artifactForm。对照上面的矩阵，它有四个"凭经验"的残留：

1. **效力没有统一坐标**。`evaluation_dimensions` 里"可复现性""内部效度""可转移性"混用，不是同一词表。
   → 新增 `validity_focus`：效力主类型，取值限定为 {内部效度, 外部效度, 构造效度, 统计结论效度, 可转移性, 效用, 循环完整性, 可复现性}。每方法必须声明，缺失即 fail-closed 拒绝加载。
2. **顺序没有理由**。`compositions.wiring` 只有顺序，没有"为什么"。
   → 每个 wiring 步骤加 `rationale`（一句话，例如"假设先于数据，防 HARKing"）。这直接回应老师那句"为何当前流程顺序如此"。
3. **没有非研究负例**。
   → 新增 `not_research` 对照区（§2.1 四行），作为注册表的边界声明。
4. **差异不可计算**。两个方法的差异目前靠人读。
   → 新增 `method_diff(a, b)`：返回证据形态、效力主类型、顺序理由三处的差异，可复现。
5. **停止规则缺失**。
   → 新增 `iteration_rule`：固定阶段 / 饱和停止 / 循环回路，三种合法形态。

这五项都是**数据层改动**，符合"加方法 = 加数据"的定位；不动治理语义，不需要动 claim/EA/closure。

## 7. 文献依据（已逐项核实）

以下论断经检索核对，标注核实状态：

| 论断 | 出处 | 状态 |
|---|---|---|
| 效度四分：内部 / 外部 / 构造 / 统计结论 | Cook & Campbell 1979；Shadish, Cook & Campbell 2002 | 已核实 |
| 受控实验 = 操纵变量 + 控制 + 随机分配 | Wohlin et al. 2012 第2章 | 已核实（**注意：准实验可无随机分配**，不能写成"所有实验都要随机"） |
| HARKing = 事后假设冒充事前假设 | Kerr 1998, PSPR 2(3) | 已核实（**不是禁止事后探索**；预注册还约束选择性分析/p-hacking，Nosek et al. 2018） |
| 案例研究 = 三角验证 + 证据链 + 分析性泛化 | Runeson & Höst 2009, EMSE 14:131–164 | 已核实 |
| 可转移性 = 外部效度的自然主义对应，依赖 thick description | Lincoln & Guba 1985 | 已核实 |
| DSR = 构建产物 + 严格评估效用；贡献三类 = 产物 / 设计基础 / 设计方法 | Hevner et al. 2004, MISQ 28(1) | 已核实（**construct/model/method/instantiation 是产物形态，不是贡献分类**） |
| SLR = 预先制定协议 + 可复现检索 + 纳排标准 | Kitchenham & Charters 2007 | 已核实（**"预先制定协议"≠现代公共预注册**） |
| ML 实验少量运行下点估计不可靠，需多种子 + 区间 | Agarwal et al. 2021, NeurIPS | 已核实（**重点是报告不确定性，不只是加种子**） |
| 理论饱和 = 新增资料不能发展类属属性 | Glaser & Strauss 1967 | 已核实 |
| 复制 = 对既有主张提供诊断性证据的新研究 | Nosek & Errington 2020 | 已核实 |

四处被修正的表述（准实验随机化、HARKing 准确含义、DSR 贡献分类、SLR 协议 vs 预注册）已写进正文，避免我凭经验写错。

## 8. 自进化边界

纪要里"自进化是否还需要固定架构"的回答，现在可以更精确：

- **L3（治理语义 / 三元组定义）**：不变，改动需代码 + SPEC + 人签。
- **L2（方法数据 / 组合接线）**：可变，但变更要走组合提案租约，且**新组合必须能回答"为什么这个顺序"**（§5 的证据依赖）。
- **L1（任务实例）**：runtime 产生。
- **交互外壳**：不变（用户侧）。

自进化可以改 L2 的方法编排，**但不能改"主张必须有可核查证据 + 效力声明"这条规则**。这条规则就是"变与不变"里那个不变的尺子。

---

## 9. 验证方式与下一步

**本文不新增代码**，是方法论建模的设计文档。它可证伪的地方在于：

1. 若某方法无法填入 §4 矩阵的证据形态 / 效力 / 顺序理由三列 → 说明它不算研究方法或建模不完整；
2. 若某组合的顺序无法给出 rationale → 说明它是经验习惯，不是推导；
3. 若 `method_diff` 算不出两个方法的本质差异 → 说明注册表字段不够。

**下一步**（按成本排序）：

1. 注册表加 `validity_focus` + 词表校验（小，纯数据 + fail-closed）；
2. `compositions.wiring` 加 `rationale`（小，纯数据）；
3. `method_diff` 计算函数（中，含测试）；
4. `iteration_rule` 停止规则（中，需先想清楚"饱和"如何判定）；
5. 把 §4 矩阵渲染进方法模型页，替代目前偏描述性的控制表（中，前端）。

## 10. 收尾一句话

老师要的"客观逻辑"不是把经验写得像逻辑，而是**让每条顺序、每个差异都能追溯到文献里的效力类型**。

不变的是"可核查 + 有效力声明"，可变的是证据形态与顺序——**而可变的部分本身也有客观依据**。这就是变与不变的关系，也是我们方法模型还缺的那一层。
