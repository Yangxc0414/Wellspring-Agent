## 4. 边界与诚实说明

1. 这是**只读展示**：不创建 Claim/EA、不改变 gate、不提供签名按钮；
2. 页面上的 rate/adjusted Δ 是**探索性 repository-mining 读数**，不是可签署结论；
3. 在线路径要求工作台与 runtime 同源（或配置代理）；GitHub Pages 上只会走静态快照，标签会显示 STATIC SNAPSHOT；
4. 静态快照由脚本生成，不是手写；但它会**随 runtime_data 变化而滞后**，属于"构建时快照"，不是实时数据。

## 6. 构建卫生补记

第一次构建后 `build_release --check` 通过但 release 完整性测试红：release 里同时存在新旧 hash 的 app chunk（vite 的 outDir 在仓库根之外，未真正清空旧 chunk；release 同步默认不 prune）。处理：

1. 删除 `site/app` 后重新 `npm run build:site`（确定性 hash，重建结果一致）；
2. `python scripts/build_release.py --prune` 删除 11 个旧 chunk 并重写 MANIFEST；
3. `test_every_file_in_the_bundle_is_explained` 转绿。

教训：**前端构建产物在仓库根之外时，必须显式清空 + release prune**，否则 MANIFEST 与磁盘会漂移；`--check` 只查源→目标漂移，不查目标里多出的文件。
