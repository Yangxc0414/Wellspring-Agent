# 认识论一号：什么算证据、允许怎么推论、顺序的理由出自哪里

**状态基线（2026-11-22）**：承接 design/174–178（流程层已数据化）。
本文补的是流程层下面那两层——**证据形态与推论规则**。这也是此前"科研本质"诊断的落地。

---

## 1. 诊断回顾（据实核查，不是印象）

| 偏离 | 核查证据 |
|---|---|
| 证据形态一元 | 前端 10 种 `artifactForm`，后端 **0 处**使用；`EvidenceArtifact` 只有一种形状；`claim` 默认 `allowed_sources=("run",)` |
| 推论规则一元 | 只有从 metrics 重算 assertion（统计口径） |
| 顺序理由无出处 | `wiring` 只有 `rationale` 文字，**没有 citation 字段**（registry 的 28 处 citation 全在 guidelines 里） |

后果很具体：**案例研究、SLR、DSR 的结论在这套系统里签不了字**——不是流程不支持，是认识论不认。

---

## 2. 本轮做了什么

### 2.1 认识论声明（`epistemics.json`）

每个方法声明四样：

```json
{
  "evidence_form": {"id":"case-corpus","label":"案例资料与编码表",
                    "hashable":"资料清单+编码表+引文索引的sha256","unit":"per-case coded pattern"},
  "inference_rule": "pattern-match",
  "rule_detail": "同一模式需在 ≥2 个独立案例中出现，且至少两类资料来源交叉印证",
  "min_independent_sources": 2,
  "constraints": [
    {"id":"triangulation","stage":"S5",
     "constraint":"结论必须有 ≥2 类资料来源交叉印证（访谈/观察/文档）",
     "citation":"Yin 2018, ch.4; Runeson & Höst 2009"}
  ]
}
```

五种推论规则（封闭词表）：`statistical` / `pattern-match` / `thematic-synthesis` / `design-cycle` / `descriptive`。
十个方法全部声明，citation 只用可核查的公开文献（Kerr 1998 HARKing、Wohlin 2012、Yin 2018、
Eisenhardt 1989、Kitchenham & Charters 2007、PRISMA 2020、Shadish/Cook/Campbell 2002、
Groves 2009、Hevner 2004、Peffers 2007、Kemmis & McTaggart 2005、Henderson 2018、Dodge 2019、
Kalliamvakou 2014）。

### 2.2 fail-closed 校验（四条硬规则）

1. 十个方法必须全覆盖，缺一个拒绝加载；
2. `citation` 必填，`TODO/待补/TBD` 等同未填写——**没有出处的顺序约束就是个人习惯**；
3. 约束阶段必须在该方法的 `fit_stages` 内；
4. **多来源规则（pattern-match / thematic-synthesis）的 `min_independent_sources` 必须 ≥2**——
   要求"多来源交叉印证"却只收 1 个来源，是自相矛盾。

第 4 条是形式自洽检查，不是文风检查。校验器第一次运行就抓到了我自己的错误：
把 case-study 的"证据先于假设"标在 S2-S3，而 case-study 的 `fit_stages` 并不含 S2-S3。

### 2.3 推论判定（`claim_support_check`）

| 规则 | 判定条件 |
|---|---|
| statistical | 至少一条数值断言且全部 `status=pass` |
| pattern-match | 同一 `pattern_id`，独立来源 ≥2，且 ≥2 类证据（三角验证） |
| thematic-synthesis | 同一 `theme_id`，独立研究 ≥2 |
| design-cycle | 必须同时有 artifact 与绑定到它的 evaluation |
| descriptive | 记录数达标，且**显式拒绝外推总体** |

### 2.4 实测（这条链是本文的核心证据）

```bash
$ python -m research_agent method support-check --method case-study --evidence ev.json
{"rule": "pattern-match", "evidence_form": "case-corpus",
 "observed_sources": 2, "supported": true, "blockers": []}
```

单案例版本：

```bash
{"observed_sources": 1, "supported": false,
 "blockers": ["rule pattern-match needs >=2 independent sources, got 1"]}
```

**这就是"最小可证伪链"**：案例研究的证据不经过 RunCapsule，也能被判为支撑或不支撑。
系统不再是实证一元论。

## 3. 与既有 run→EA→claim 的关系（不是取代）

- `run claim`（`source=run` + metrics 重算）**原样保留**——它对受控实验是正确的；
- 本轮新增的是**平行的另一条路**：按方法的 `evidence_form` + `inference_rule` 判定；
- 两条路都**只判定、不签署**——签名仍在 CLI/人工流程。

所以这不是"放松证据要求"，而是"承认不同方法有不同的证据形态"。

---

## 4. 可证伪主张

1. 若某方法的约束无 citation，加载必须失败 → 已实现并有负例测试。
2. 若把 case-study 的 `min_independent_sources` 改成 1，加载必须失败（规则自洽）→ 已实现。
3. 单案例 claim 必须判为不支撑 → 已实现，且有 blocker 文案。
4. 若 `survey` 的 claim 声明外推总体，必须判为不支撑 → 已实现。

---

## 5. 边界（诚实）

1. **只做判定，不接管签署**：`claim_support_check` 不产生、不签署 Claim；
   `run claim` 的 CLI 路径未改，非实验形态的"签署"仍需人把判定结果写进 claim 并签。
2. **只做声明层**：十个方法的 `evidence_form` 是声明，不是"系统能自动采集这些证据"。
   案例资料、访谈编码的采集管道仍未实现——这条链目前是"能判定"，不是"能生产"。
3. **citation 的正确性由人保证**：我列的都是真实存在的文献，但没有逐条核对页码与表述；
   论文引用前需人工复核。
4. 五个方法（quasi/benchmark/survey/DSR/action）的约束我只写 1–3 条，是**起步集不是完备集**；
   状态标 `modeled` 指"已声明并可判定"，不指"方法论已穷尽"。
