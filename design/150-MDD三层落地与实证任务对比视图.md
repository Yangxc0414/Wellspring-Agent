# MDD 三层落地与实证任务对比视图：同一治理骨架，不同实例化

> 状态基线：2026-11-21。承接 149（方法原模型上屏）、147（断言指向清晰化）、145（人的表述上屏）。
> 本文新增前端对比派生（`apps/web`）与一处此前遗留的 python 快照同步；不新增任何断言数字。

---

## 0. 一句话结论

MDD（模型驱动设计）在本系统里不是口号，而是**三层结构**：元模型 = 治理不变式（门/链/签/槽位），模型 = 方法注册表（9 种方法 × 协议字段 × 检查），实例 = 每个研究任务会话（SESSION PATH）。上一轮把元模型与模型层上屏；本轮补第三层的**对比呈现**：设置 → 方法模型新增「实证任务对比」——三个实证任务在同一治理骨架上的实例化差异一表可读（方法 profile、证据源、主指标、seeds、**基线策略**、断言主张+范围、已走槽位、开着的人工门），外加两种方法的协议字段并排对比。

## 1. MDD 三层在本系统的落点（反思）

| MDD 层 | 本系统对应 | "不变/可变" | 呈现位置 |
|---|---|---|---|
| 元模型（meta-model） | 治理不变式：九槽位、门 Q0/G1/G2/S5b/G5、span-only、claim 三元组、EA 不可变、closure/lineage | **不变** | STAGE_MODULE_CONTRACTS、方法模型页槽位卡 |
| 模型（model） | 方法注册表：每种方法的 fit_stages、须冻结的协议字段、blocker 检查、cannot_support、方法学引用 | **半可变**（数据声明，加方法=加数据） | 方法×槽位矩阵 + 方法详情卡 |
| 实例（instance） | 每个研究任务会话：SESSION PATH、run/claim/断言范围、开着的门 | **可变** | SESSION PATH + 本轮实证任务对比表 |

**设计复杂性体现在分层而不是分支**：不为每种方法写一条流程（149 的主张），而是让方法作为数据声明"我占用哪些槽位、冻结什么、不能支持什么"；治理槽位与门对所有方法同一套。这正是"以原模型为指导进行智能体设计"的可执行形态。

**方法创新点（呈现层）**：实证任务对比表把"受控实验 vs 仓库挖掘 vs 演示代理指标"的差异落到具体维度——尤其是**基线策略**一行：两条真实运行都是"无配对基线读数——只报均值/差值与检验，不宣称超过基线"（min_delta not_verifiable），教学演示则有一条配对基线 -0.048；同一列里还能看到断言范围的真实差异（三仓库便利样本·不可外推 vs 本地协议验证）。这是静态架构图给不了的"方法差异实证化"。

## 2. 实现

- `domain/taskCompare.ts`：纯派生——固定对比顺序（ESE → E2E → 教学版），每任务派生方法 profile、证据源、主指标、seeds、**基线策略**（run.baseline 为空 → "无配对基线读数…"，绝不伪造 delta）、claim（id/徽章/scope/截断主张）、已走槽位（transcript stage 标签）、开着的人工门。
- 方法模型页两个新区块：**协议字段对比**（仓库挖掘 vs 受控实验的 protocol_fields 并排 + blocker 检查清单）与**实证任务对比**（转置表：维度为行、任务为列）。
- 空态与边界：未映射任务不进表（isComparableTask）；注册表缺失时方法对比为空但任务行仍可派生；对比全部来自任务自身字段与转录。

## 3. 已实测

- `node --test tests/taskCompare.test.ts` 5/5（对比顺序与未映射任务剔除、基线策略声明与反伪造 delta 断言、claim 徽章诚实性——委托签不得读作人签、已走槽位与首槽原话引用、方法对比空态）；typecheck 通过；全量 `test:unit` 46/46。
- 静态构建实测：对比表三列渲染（方法 profile/证据源/主指标/seeds/基线策略/断言/已走槽位/开着的人工门），协议字段并排对比渲染；截图确认。
- `docs_audit` / `repo_hygiene` / readiness / 发行副本 `--prune` + 完整性测试通过。

## 4. 设计主张（可证伪）

1. 对比视图的正确数据源是**各任务自身字段**，而不是再写一份对比文案——任何一行都能指回 run/claim/gates/转录；
2. 基线策略是最能区分实证方法可信度的单一维度：not_verifiable 的如实呈现比一个漂亮的 delta 更能证明治理在起作用；
3. 该对比表天然就是**论文实验章的素材**：把三个任务换成真实多方法任务集后，这张表直接展示"系统支持多方法且治理等价"。

## 5. 边界与下一步

- 对比目前限定三条映射过的 seed 会话；runtime 任务携带 method_id 后进同一张表（acceptance 已在 149 §4）；
- "已走槽位"计数仍是 executed 语义（ESE 5/9），与叙事完备性（25 条消息）分开呈现——是有意的；
- 方法×槽位活动名的逐格文本（90 格）仍按 148 的"逐字有据"原则等待真实多方法会话积累。
