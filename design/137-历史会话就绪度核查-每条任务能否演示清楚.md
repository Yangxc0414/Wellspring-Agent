# 每一条历史会话是否都演示得清楚——一次以任务为单位的就绪度核查

- 状态基线：2026-11-20；对象为前端种子工作区 7 条活跃会话（另有 1 条归档）
- 触发问题："确定前端的历史会话各个都能演示清楚？这个 ESE 任务 吗？"
- 结论：**修之前不能。**问题不在"内容多少"，而在同一屏互相矛盾、以及三个面板不随任务切换。

---

## 1. 核查方法

不读代码猜，而是用无头浏览器逐条点开每个任务，记录：消息数、卡片数、正文字数、右侧 8 个 tab 各自的字符数，并监听 4xx / JS 异常。再对可疑任务把面板原文整段导出对照。

这一步本身就是结论的一部分：**"能不能演示"是一个可测量的事实**（有没有内容、有没有 404、两处数字是否一致），不是主观评价。

## 3. 三个真缺陷（均已修）

### 3.1 ESE：同一屏说两套话（最严重）

- 对话与 S5 门：`RunCapsule ✓ completed` / `EA ✓ immutable EA-65d32e114229`
- EVIDENCE 面板：`运行记录 not run` / `证据制品 not sealed`

根因是种子数据 `run: null`、`evidence: []`：**机制是假的**——结构化记录没建，但门禁和对话都按"已有 EA"写。这属于本项目最不该出现的缺陷类型。

修法不是改文案，而是补数据：按 `runtime_data/ese-ms-20261118-03/run/` 的真实产物建 `run`（metric `test_cochange_rate`、mean 0.3749、EA `EA-65d32e114229`、seed 42），并加一条 `unsigned` 的 claim（CLM-ESE-01），让"待人工签署"落在一个真实存在的断言上。

### 3.2 ESE：门禁序列不可能成立

`G1 needs_human`、`G2 needs_human`，但 `S5 pass`——运行不可能先于设计门通过而执行。RUN 因此显示 `WAIT G1`，同时右侧写着 `EA immutable`。

修法：G1/G2 改 `pass`（协议冻结、run-capsule 绑定 protocol sha256 都是事实），G5 保持 `blocked`。现在 RUN 显示 `WAIT G5`，与对话一致。

### 3.3 run 卡片按钙钛矿硬编码

卡片写死 `MEAN T80`、单位 `h`、脚注"数值是演示数据"。把任何别的任务的读数放进去都是错的：

- ESE 的真实指标 `test_cochange_rate` 会被标成 T80 小时；
- E2E 的 `BASELINE 0 / DELTA +0.956` 与正文"min_delta 不可验证、不能宣称超过基线"**直接冲突**。

修法：卡片改为**由数据驱动**——标题用 `card.metric`，单位可选 `unit`，`baseline` 允许 `null` 且为 null 时不打印 DELTA（显示 `—`），脚注改为每条运行自带 `note`。同时把 E2E 的 `baseline` 从 `0` 改为 `null`，因为那 0 是编出来的。

## 4. 两个"看起来能用、其实不随任务变"的面板

- **`演示流程`**：是通用九阶段教学模板。选中 ESE 再点它，会讲"自改进提案"的故事。现在非「完整闭环」任务下标题改为「全流程演示 · 通用模板（非当前任务）」，并明确"这里演的不是这条任务的流程，真实读数看左侧会话与 BRIEF/RUN/EVIDENCE"。
- **RUN 顶部角标**：所有非 runtime 任务一律标「演示数据」。ESE 是真回放、E2E 是 fixture 真实执行，这个标签同时**低估**前者、**放大**后者。现在在数据层加 `replay.basis`（real / fixture / demo），RUN 分别显示「真实回放」「FIXTURE · 真实执行」「演示数据」。

`EVOLUTION` 与 `ESE 运行` 仍然跨任务一致，但检查后确认它们是**全局面板**且已自带说明（"独立证据臂 · 与当前任务的演示候选分开"），不属于缺陷。

## 5. 两个薄示例补成"有边界的最小故事"

`证据驱动科研写作系统` 与 `项目命题设计与反思` 原来只有"任务已创建 + 一张卡"，读者不知道它为什么停。现在各补一条用户提问与一条收尾门禁：

- 写作：问"能不能先写 Results" → 四个槽位 locked → 门禁卡 `S8–S12 blocked`，并说明"下一步不是先写一版，而是回 S5 人签"。
- 命题：问"命题很散怎么收敛" → 给出验证顺序（先证明门禁会卡 → 再证明判定可重算 → 最后谈自动化）→ `G1 needs_human`。
- archive 示例：补一句"这一条只到检索计划，不往下走"，并指向完整闭环任务。

顺带修了写作任务的阶段自相矛盾：`stage = 6` 但所有阶段 pending，RUN 会说 `NEXT S1`。现在 `autoStages` 前 6 个标 done，RUN 与标题都落在 S8–S12。

## 7. 诚实的剩余边界

1. 七条会话里只有 ESE 是**真实语料 + 真实数字**；E2E 是真执行但语料是 fixture；完整闭环是教学演示。三者现在各自标了 basis，不再共用一个"演示数据"标签。
2. **没有一条是"真人签完的完整闭环"**。ESE 的 claim 仍 unsigned，E2E 是 autopilot 委托签。组会若要演示"签署完成"，只能在完整闭环任务里用 DEMO 预览，并当场说明这是界面预览。
3. `演示流程` 面板仍然是教学模板，不会为每条任务重演它的真实流程。这是设计取舍（成本 vs 价值），已用标题与横幅讲清，但观众若只看这个 tab，看到的仍不是 ESE 的流程。
4. `EVAL` 的基线/隐藏集仍是 SIM（设计如此），不适合在组会上当实验读数引用。
