# 人的表述上屏：同一任务里的人话按阶段可见、可点、可签

> 状态基线：2026-11-21。承接 141（人工门对话化）、143（会话阶段路径）、144（显示细节）。
> 本文只改前端显示（`apps/web`）；人话全部逐字来自会话转录，不新增内容、不改契约。

---

## 0. 一句话结论

审计面板时发现一个系统性缺席：**人自己在同一个任务的对话里说过的话**——开场诉求、G1/G2 决策、追问、确认——只以 "YOU" 气泡在转录里一闪而过，右栏所有面板和演示里都没有它们的位置。本轮把人的表述派生上屏：BRIEF 新增 HUMAN TURNS 段（按阶段归属、点击定位原话），会话阶段路径节点显示"人×N"并引用原话，人工门对话框引用本会话人的原话并用**决策型原话预填 human_reason**——人的话直接进入签署命令。

## 1. 派生规则（humanTurns）

与 `demoStageSpans` 同一条 span 吸收规则：无标签消息归入前一个阶段段，人的发言按所在段归属阶段；首个阶段标签之前的发言归"开场"。**决策识别是保守的**：只有以 `G1：/G2：` 这类门 ID 前缀开头的话才算决策引句——"这条现在能签吗？"是追问，永远不会被预填成 human_reason。单测 4 例钉住全部规则（吸收/分组/决策识别/空态）。

## 2. 三处上屏

| 位置 | 内容 | 交互 |
|---|---|---|
| BRIEF · HUMAN TURNS · 人的表述 | 全部人的发言：阶段 chip + 时间 + 原文（截 64 字） | 点击 → 会话滚动定位到那条原话并闪烁（新增 `focusMessage` 机制，与阶段跳转同机制、按消息 id） |
| 会话阶段路径节点 | 有人的发言的阶段节点显示"人×N"徽标；展开体引原话（截 80 字） | 点击引用行 → 定位原话 |
| 人工门对话框（G1/G2/G5） | "本会话里人的原话"块，决策型引句高亮 | 决策引句自动预填 human_reason（可改），实时进入 CLI 命令——人的话直接成为签署理由 |

诚实边界：原话逐字引用不截改（面板只截显示长度）；未揭示的播放中面板显示最终列表，由播放条常驻声明兜底（既有纪律）。

## 4. 设计主张（可证伪）

1. 人的表述的正确投影单位是**阶段段**而不是时间线：与阶段跳转共用同一条 span 规则，BRIEF 里的"文献检索 · 10:01:05"让人一眼看到"人在这个阶段说了什么"；
2. **决策引句识别必须保守**（门 ID 前缀开头）：追问预填成 human_reason 就是替人做决定——测试把"这条现在能签吗？"钉死为非决策；
3. human_reason 的最佳来源是人的原话本身：对话框预填 + 可改，比空白模板更能防止"为了过门而编理由"。

## 5. 边界与剩余差距

- 人在 runtime 模式通过 Composer 输入的内容同样进 `messages`（role=user），本投影自动覆盖，无需额外接线；
- 追问（非决策）暂不与"它引出的下一条 agent 消息"建立问答对展示——可作为后续打磨；
- GateDialog 的决策引句识别只覆盖 G1/G2 前缀型话术，G5 的确认型话术（"确认导出"）未出现于种子会话，暂无样本。
