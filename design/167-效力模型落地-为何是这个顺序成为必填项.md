# 效力模型落地：把"为何是这个顺序"变成注册表里的必填项

> 状态基线：2026-11-21。承接 166（研究方法与研究流程的变与不变）。166 是设计主张，本文是它的实现与实测。
> 改动面：`modules/method-registry`（schema 0.5→0.6，SPEC 0.3.0→0.4.0）+ 方法模型页；不动 claim/EA/closure/门禁。

---

## 0. 一句话结论

166 提的五项改造全部落地：**效力主类型（封闭词表）、停止规则、每步接线的顺序理由、非研究负例、方法差异可计算**。

落地后最直接的变化是：**注册表从一个"记录顺序"的表，变成必须回答"为什么是这个顺序"的表**。任何接线步骤缺 `rationale`、任何效力值不在词表内，加载即拒绝。

## 1. 五项改造的落点

| 166 的建议 | 落地形态 | 失败模式（fail-closed） |
|---|---|---|
| 效力主类型 | 每方法 `validity_focus: {primary, secondary}`；顶层 `validity_vocabulary` 9 项 | 主/次类型不在词表、主类型重复出现在次类型 → 拒绝加载 |
| 顺序理由 | 两种组合共 18 个 wiring 步骤，每步必填 `rationale` | 任一为空 → 拒绝加载 |
| 非研究负例 | 顶层 `not_research`：纯工程交付 / 纯经验报告 / 只有 SOTA / 事后假设冒充预测 | 缺 label/missing/why 或 id 重复 → 拒绝加载 |
| 差异可计算 | `method_diff(a,b)` + CLI `method diff` | 未知方法 → `MethodRegistryError` |
| 停止规则 | 每方法 `iteration_rule: {kind, detail}`，四种：fixed / saturation / cycle / convergence | kind 不在枚举、detail 为空 → 拒绝加载 |

同时修掉两处 `method_id` 变量遮蔽（标签循环与组合绑定循环都在用上一轮的残留变量），这与 162 修过的 `stage_ids` 遮蔽是同一类问题。

### 2.1 差异函数实测

`method diff controlled-experiment quasi-experiment`：

- 效力主类型**相同**（都是内部效度）；
- 证据源差异给出 `only_a: ["分配与偏离记录（随机化留痕）", …]`；
- 这正好把 166 里那条修正落成了结构：**准实验不需要随机化，所以它的证据集里没有随机化留痕**，而不是"准实验效度更低"这种含糊说法。

`method diff repository-mining case-study`：

- 效力不同（构造 vs 可转移）；
- 顺序首处分歧 `index 0: S4 vs S0`；
- 停止规则不同（fixed vs saturation）。

这三条差异都能被第三方复算，不依赖读文档的人的经验。

## 3. 落地时被迫做的四个判断（记录下来供讨论）

1. **"判别力"要不要进效力词表？** 它不是 Cook & Campbell 四分里的任何一类。我把它作为**ESE 工程实验的扩展**显式标注（词表文案里写明），而不是硬塞进"构造效度"。理由：消融能否区分模块贡献，确实是 ML 实验的核心判据，但它不是"操作化是否代表构念"。
2. **案例研究是否饱和停止？** Runeson & Höst 不强制饱和，所以 `iteration_rule.detail` 写成"须在协议中声明是否采用"，把选择权交回协议，而不是替方法做决定。
3. **ML 迭代是固定轮数还是收敛停止？** 设成 `convergence`，detail 明写"不以固定轮数代替收敛判据"。这是一条会约束未来执行的声明，可能被质疑"如何判定收敛"——但写成 fixed 会与该方法的实践不符。
4. **SLR 是 fixed 还是 saturation？** 选 fixed：协议与截止日期冻结是它的效力来源；饱和属于扎根理论，不适用于 SLR。

这四条都不是"数据填表"，而是需要在文档里留痕的判断。

## 4. 前端呈现

方法模型页新增/修改三处：

1. **研究方法 × 效力类型**：10 行 × 5 列（方法 / 效力主类型+次类型 / 证据形态 / 停止规则 / 组合），表下附 9 项词表与"不算完整研究"的边界；
2. **方法详情卡**：证据块新增"效力主类型"与"停止规则"两行，逐字来自注册表；
3. **要素组合视图**：每个接线步骤多一行淡色理由（共 18 条），并把标红从"固定标方案"改成**首个分歧位置**——验证式标"假设"、探索式标"方案"，因为差异在顺序，不在某个固定要素。

实测：表格 10 行渲染、18 条理由全部出现、无 4xx/JS 错误。

## 5. 仍然没解决的

1. **`method_diff` 只在 CLI**，前端还没有"选两个方法并排对比"的入口；目前靠表格 + 详情卡人工对照。
2. **停止规则只是声明**：`saturation` / `convergence` 如何判定，执行器还没有消费它（与 165 的结论一致：执行层仍是固定链）。
3. **非研究负例只是边界声明**，没有接到任何校验上——注册表不会因为一份"纯经验报告"而拒绝什么，因为没有入口接收它。
4. **L2 的组合提案租约**仍是 roadmap：现在可以改数据，但改数据的权限流程还没建。
