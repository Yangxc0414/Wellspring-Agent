# 反思：研究的本质是什么——从第一性推导原模型，再回头看系统

> 状态基线：2026-11-21。承接 149/150（方法原模型与 MDD 三层）、151（证据即研究本质与要素组合图）。
> 本文是纯反思 + 一处上屏（方法模型页顶部"研究的本质 · 原模型"卡 + 九方法的证据类型与效力）；注册表本体与后端未动。文献依据按纪要要求全部取自学术界既有理论，不凭直觉。

---

## 0. 一句话结论

把"研究的本质是什么"按学术界既有理论推导到底，得到一个比"证据"更完整的表述：**研究是在公共可核查的约束下，把一个问题转成能判别候选答案的证据，再把证据转成经审查、带范围的主张，并积累进公共知识的循环。** 用这个定义回头审我们的系统：治理机器（门/链/签/沿袭）确实从本质推导出来了；但有三处**系统的设计还没有从本质推导出来**——判别力分析不是一等要素、知识增量没有建模、组合拓扑单一。这三处登记为 roadmap，且都标注"属元模型层，需后端 SPEC 先行"。

## 1. 从既有理论推导"研究的本质"（调研）

| 理论来源 | 对本质的贡献 | 在系统中的对应 |
|---|---|---|
| Popper《科学发现的逻辑》（1959）：可否证性 | 研究的起点不是"验证"而是**承担风险的猜想**；设计的价值在于它能否区分猜想的真假 | 候选假设（CAND/IDEA，不是 claim）；设计审计——但"该设计能否判别该假设"尚无一等关系（差距 G1） |
| Merton 1942（organized skepticism） | 研究是**制度化的怀疑**：怀疑必须被组织成实践（评审、复现、 communal scrutiny） | 人工门 + 评审包 + closure + lineage = 组织化怀疑的机器 |
| Longino 1990《Science as Social Knowledge》 | 客观性不是个人的，来自**批判性 discourse** 的转换 | 独立评审、多评审 rubric、签署来源强制披露 |
| Creswell《Research Design》（2014）：研究设计 = 世界观 + 策略 + 方法 | 方法差异是**要素框架**的差异（问题/文献/程序/效度/结论） | 方法注册表的 protocol_fields/threat_focus/cannot_support |
| Easterbrook et al. 2008（实证方法选择） | 不同方法产出**不同类型的证据**（问卷自报 vs 受控测量 vs 挖掘观察），效力与威胁各异 | EVIDENCE_PROFILES 九方法证据类型（本轮上屏） |
| 注册表既有引用（Kitchenham 2007 / Wohlin 2014 / PRISMA 2020） | SLR/实验的可复现协议规范 | 协议字段与检查项 |

**推导出的本质定义**（按上表合成）：研究是在公共可核查的约束下，把一个问题转成**能判别候选答案的证据**，再把证据转成**经审查、带范围的主张**，并**积累进公共知识**的循环。三个关键词缺一不可：判别力（否则证据无效）、审查（否则主张不可信）、积累（否则不叫知识）。

## 2. 用这个定义回审系统：三处尚未从本质推导出来（诚实差距）

| 差距 | 本质层面的缺失 | 现状 | Roadmap（元模型层，后端 SPEC 先行） |
|---|---|---|---|
| **G1 判别力不是一等要素** | 设计必须能区分假设真假（Popper 的核心）；目前只有受控实验有 power_analysis 字段，且与假设无绑定关系 | 设计审计查 blockers=0，不查"该设计对该假设的判别力" | S4 协议新增 `discriminating_for: <hypothesis-id>` 一等字段 + 审计项 |
| **G2 知识增量没有建模** | 研究的循环性：主张成立后**公共知识记录发生了什么变化** | claim 签署后流程结束，无"增量声明" | claim 增 `knowledge_delta` 声明（哪条已知被更新/推翻/加限），与 S1b 矩阵联动 |
| **G3 组合拓扑单一** | 探索式方法（扎根/案例）合法地"先证据后假设"，且可迭代 | 九槽位是一条固定拓扑链；fit_stages 不表达顺序 | 方法 profile 声明合法拓扑（151 §4 的组合租约承接） |

这三条都**属于元模型层**：改它们 = 改门禁语义与产物契约，必须走 SPEC + 后端实现 + 治理不变式回归，不是前端能补的。前端的职责是把差距**摆上屏**（本轮）而不是假装不存在。

## 3. 本轮上屏（方法模型页顶部）

1. **研究的本质 · 原模型卡**：定义（上面 §1 的合成句）→ 三层卡（主张层 ClaimRecord / 证据层 RunCapsule+EA / 审查层 门+评审+closure+lineage=组织化怀疑的制度化）→ **要素映射表**（9 行：问题/已知/猜想/方案/证据/推断/主张/审查/积累 ↔ 系统对象）→ 文献依据行（Popper/Merton/Longino/Creswell/Easterbrook）。
2. **方法详情卡增"证据类型与效力"**：九方法各一条类型判定（一手受控测量/一手分组观察/标准化任务测量/回顾性观察挖掘/二手综合/个案深描/自报测量/设计制品评估/介入循环反思）+ 效力说明；类型判定为经验方法论标准分类（Easterbrook/Creswell），效力边界逐字取自注册表 cannot_support。
3. 单测 3 例：九方法全覆盖有据、受控实验与自报调查的"本质差异"必须体现在类型上、未知 id 不发明画像。

## 4. 设计主张（可证伪）

1. "研究的本质是证据"必须精化为"证据的**判别力** + 主张的**范围** + 审查的**制度化**"——只说证据会把系统带向"收集一切"，漏掉"证据必须能区分答案"（G1 差距因此暴露）；
2. 方法差异的本质单位是**证据类型**，不是步骤数：九方法的矩阵之所以成立，是因为每一列的 cannot_support 指向不同的效力边界；
3. 元模型层的差距（G1/G2/G3）是毕设**下一阶段最值得做的研究内容**——它们都有明确的文献来源与可执行的验收形式，且每个都会牵动数据流（正是纪要"顺序调换牵动整个数据流"的印证）。
