# 进展反思：从“能跑”到“谁有权说更好”——FlashRSI、Harness² 与我们自己的准入

> 状态基线：2026-11-20。承接 76/121（FlashRSI 首跑与分级）、120/126（Harness² 机制与桥接）、135（Agent4Sci 任务对照）、137–138（demo 就绪度与内容）。
> 本文不产生新实验读数，只把已有事实重新组织成一个判断。

---

## 0. 一句话结论

这一阶段的进展不是“功能变多了”，而是**同一套准入纪律从后端一路贯彻到了演示**：claim 的来源要标、委托签不能算人签、run contract 不成立就不许印 delta、连教学面板都要说明自己不是当前任务。

但这条纪律**还没有贯彻到我们自己身上**：我们要求一条研究结论必须有人签、有 EA、有 closure、有沿袭，却允许“平台自身的改进”只交一份提案加一个租约。这是我们最该反思的双标。

---

## 1. 进展怎么读：四次转向，而不是四堆功能

回头看，这段工作其实转了三道弯，每一道都是被具体缺陷逼出来的：

| 阶段 | 当时的目标 | 逼出它的缺陷 | 留下的方法 |
|---|---|---|---|
| **能跑** | 模块齐、测试绿 | 各模块自说自话 | 单一事实源、契约测试 |
| **自洽** | 同一事实多处一致 | 同一个 claim 三个 tab 三种说法；ESE 对话说 EA 已封、证据链说没跑 | 数据层标注（origin / replay.basis），不靠文案补 |
| **可演示** | 每条会话都能讲 | 7 条里 4 条 NEXT 指向错误动作 | 逐任务代入角色读，而不是读代码 |
| **可核查** | 判断本身可重复 | 我截图把 5/9 看成 8/9 | DOM 测量 + `check_task_readiness.mjs` |

四次转向的共同点：**每次都是“看起来对”被一个具体反例打破**。这也解释了为什么最后留下的不是更多功能，而是几条更硬的纪律——单一事实源、数据层标注、逐任务实测、判断脚本化。

### 现在的真实状态

| 已经成立 | 仍未成立 |
|---|---|
| 9 阶段执行 + 5 项门禁（Q0/G1/G2/S5b/G5，其中四项人工） | 没有一条**真人签完**的完整闭环 |
| claim / EA / closure / lineage 四件套 + verdict 读时重算 | 没有**跨引擎同题对照** |
| 7 条会话逐条可演示，3 种 replay basis（real / fixture / demo） | 阶段声明三头分裂（9 阶段 / S0–S16 / 35 个 SPEC） |
| 演示里的“不可宣称”被显式标注（fixture、委托签、demo 签） | EVAL 与 guidance 仍是 SIM，无后端 |
| 判断可脚本复跑（就绪检查 + 内容断言） | L2 官方路径（Docker / 外部 key）未验证 |

一句判断：**工程跑道基本铺完了。**继续打磨界面的边际收益在下降，瓶颈已经转到证据——不是“界面还能不能更好”，而是“我们凭什么说这个更好”。

## 2. FlashRSI：复现真正教会我的，不是“它能跑”

### 2.1 分级比“跑通”有用

把“跑通”拆成四级之后，汇报的语言立刻变干净了：

| 级别 | 含义 | 当前 |
|---|---|---|
| L1 最小端到端 | 官方代码真跑一圈：算法→harness→评分→选择→产物 | ✅ |
| L1.5 效应演示 | 基线不满分的题池上出现“被采纳的改进” | ❌ 题池饱和 |
| L2 官方路径 | Docker + 外部模型 API + 上游 31 基准 | ❌ 无 Docker/key |
| L3 受治理接入 | 进 ExecPort dispatch + claim/closure/lineage | ❌ 直跑 CLI |

**“跑通了”这三个字在答辩语境里会被自动读成 L2。**说“完成 L1 最小端到端”，既准确，又把缺口变成了可执行的下一步。这不是自我贬低，是把一个模糊的成功感换成三个明确的缺口。

### 2.2 `accepted = false` 是整个复现里信息量最大的一行

基线 1.0、候选 1.0，系统**拒绝替换**，保留原快照。

我原来的直觉是“没涨分＝没成功”。后来才想明白：这一行证明的不是演化失败，而是**门真的会拒绝**。在 12 题、基线满分的池子里，唯一能观察到的就是准入语义；而“平局拒收”恰好是它最该被观察到的行为。

这对我触动很大，因为**我们平台最缺的正是这种“可观测的拒绝”**。我们的门禁全是自己写的：G1 待人工、G2 待签、G5 阻塞——它们当然会显示“阻塞”，可那是我们让它显示的。我们没有任何一次“系统拒绝了它本可以接受的东西”的实测记录。FlashRSI 用一行 `accepted=false` 做到了。

### 2.3 “没改上游代码”≠“走了官方路径”

`localqa` 是上游 README 明确支持的扩展方式（运行时注册、`Task.env=None`、复用同一份数据/prompt/评分），零上游改动。但它是**本地扩展**，不是 SearchQA 官方结果，分数不可比榜单。

这两件事必须分开说：
- 零改动 → 说明我们没有为了跑通去篡改评测；
- 本地扩展 → 说明这不是官方路径，分数没有对外可比性。

把它们混成一句“我们在 SearchQA 上跑通了”，就是越界。

### 2.4 复现是一种论文替代不了的阅读

读论文不会告诉你：31 个 benchmark 全部要 Docker；httpx 会因为在 `NO_PROXY` 里看到 `[::1]` 直接崩；宿主 shim 的模型名不能带 `gpt-` 前缀，否则会走 Responses API。

这些“不体面”的事实——环境墙、崩溃、token 全 0、平局——恰恰是**研究里最该被记录的部分**，而论文通常不写。复现的价值不是确认结论，而是生产这些被省略的事实。

## 3. Harness²：四个机制，一个反直觉

### 3.1 四个机制

1. **预算恒等式是硬不变式**：`R=4k`、`P=3k`。桥接实测 `R=16/16、P=12/12`。
2. **选择与评分分离**：选择在匿名化候选里做，**没有真值参与**；judge 是事后测量，方法根本不 import 它；judge 失败返回 `None` 而不是 0，`None` 从分母剔除。
3. **grader tripwire**：agent 产出的树在入库前扫评分标记，命中即拒——“这样的树之后不能被当作证据”。
4. **经验库整树携带**：采纳的 harness 整树保存、绝不摘要；lesson 必须 `cue / lesson / evidence` 三字段齐全。

### 3.2 最反直觉的一点：先查重复 label，再查计数

`assert_identity` 不是先算总数，而是先查有没有重复 label。因为**重复 label 能满足计数**：两个阶段写了同一个 run id，总数看起来对，实际有一个候选被静默覆盖。

这条设计对我的启发是：**算术成立不等于语义成立**。我们的 closure 16 项检查里也有同类风险——四项产物“都在”不等于“都对得上”。`ea_id_matches`、`protocol_artifact` 这些检查之所以必要，就是因为“存在”不能推出“一致”。

### 3.3 平局处理相反，但都对——平局策略是准入语义的指纹

FlashRSI 有真值：平局意味着“没有改进证据”，必须拒。
Harness² 没有真值：选择是偏好表达，不需要用“严格改进”来证成，judge 只做事后测量。

同一件事（平局怎么办），两个系统给出相反答案，而两个答案在各自的前提下都正确。这让我意识到：**准入语义不能脱离“有没有真值”单独讨论**。我们平台的人签门之所以不能被自动化替代，也是同一个道理——研究结论的“更好”没有可自动计算的 ground truth，只能由人对 statement 负责。

## 4. 三者放在一起：准入的三层，不是能力的三档

| | FlashRSI | Harness² | Wellspring（我们） |
|---|---|---|---|
| 准入对象 | **改进**（skill 文本） | **候选**（harness 树） | **结论**（claim） |
| 判据 | dev 严格改进，真值在环 | 匿名行为对比 + 事后 judge | 人签 + closure 读时重算 |
| 平局/失败 | 拒收，保留现任 | judge 失败剔除，不当 0 | 待签/阻塞，负结果保留 |
| 证据形态 | 不可变 snapshot + 全轨迹 | 整树 + cue/lesson/evidence | span / EA / closure / lineage |
| 预算纪律 | edit budget / max steps | R=4k / P=3k 硬恒等式 | autopilot 策略 SHA-256，越界即停 |

**它们不是“谁更强”，而是“谁有权在哪个层面说更好”。** FlashRSI 决定一次 skill 改动值不值得留下；Harness² 决定预算内哪个候选值得采纳；我们决定一条结论能不能写进论文、能不能导出。三层可以串联，不能互相替代。

这也回答了“科研智能体到底比什么”：不是比谁生成的论文多，而是比**谁的选择可复核、谁的证据可追溯、谁的经验可准入**。

但必须说清：**这张表目前是结构判断，不是实验结论。**三者的共同任务面（localqa 的 12 题池）已经具备，但还没有在同一题池上做过对照。

## 5. 我们自己的双标（本文最该被记住的一节）

我们对一条研究结论的要求：

- 来源要可定位（span），摘要-only 不算证据；
- 运行要封成 capsule，结果要哈希成 EA；
- closure 要 16 项逐条核对；
- claim 必须由人在 CLI 签署，浏览器不许代签；
- 委托签必须标 `submission=false`，不能算人签。

我们对自己平台改进的要求：

- 一份提案（target / patch / rationale / predicted）；
- EV1–EV4 四个问题；
- 一个租约；
- ——**没有一次“改进 vs 现任”的受控测量，没有 accepted/rejected 的实测记录。**

这就是双标。**我们用最严的标准要求研究结论，用最松的标准要求自己。**

更具体地说，我们缺少的是 FlashRSI 那句 `accepted=false` 的对应物：一次“候选更好，但证据不足，所以拒绝”的真实事件。没有它，“自进化”永远只是提案流程，不是能力。

Harness² 也给了我们一把尺子：预算恒等式。我们的 autopilot 有策略哈希、有越界即停，但没有一条像 `R=4k` 那样**可以被机器断言、可以被外部复算**的预算恒等式。

**结论：治理不应该只向外。**下一步最值得做的，不是再加一个门禁界面，而是让平台自身的改进也走一遍我们对 claim 要求的那条链：固定题池、预注册判据、成对比较、负结果落盘。

## 6. 共同任务面：有了，但对照还没做

`localqa` 的 12 题池现在可以被三个引擎共用。现状是：

- FlashRSI：已跑（L1，`accepted=false`）；
- Harness²：桥接通过（`R=16/16、P=12/12、10/10 checklist`），但 `simulation=true`、`claim_eligible=false`——**它测的是接缝，不是能力**；
- 我们的 pipeline：尚未在同一题池上跑。

所以“三引擎正交”目前是**结构判断**。真正的对照应该比什么？不是分数高低，而是：

> 同一个任务上，三套准入分别**拒绝**了什么、**接受**了什么，理由能不能被第三方复算。

这比“谁高几分”有意义得多，也更符合我们自己的证据观。

---

## 7. 真实缺口（按严重度）

1. **没有真人签完的完整闭环。** demo 里三条带 run 的会话分别是：真实语料待签（ESE）、fixture 委托签（E2E）、教学演示（完整闭环）。没有一条是“作者签了、closure 通过、导出成功”。
2. **没有跨引擎同题对照。** 共同任务面具备，实验未做。
3. **阶段声明三头分裂。** 代码 9 阶段、设计 S0–S16、35 个 SPEC，三者无机器映射。
4. **EVAL 与 guidance 仍是 SIM。** 前端有面板，后端零命中。
5. **L2 未验证。** 没有 Docker、没有外部 key，官方路径的隔离语义没跑过。
6. **token 仪器缺口。** 12 次调用全 0，不是零成本，是 shim 不报用量。

## 8. 下一步：三个最小动作，每个带判据

| 动作 | 成本 | 判据（做到什么算完成） |
|---|---|---|
| **A. ExecPort 注册 `flashrsi` 面**（L3） | 小 | 一次外部引擎运行在链上留下 capsule/EA，closure 能读到它，而不是“文件夹里的证据” |
| **B. localqa 难题池 + 预注册判据**（L1.5） | 中 | 出现一次 `accepted=true` 且 sealed test 方向一致；若未出现，如实报“未观察到改进” |
| **C. 三引擎同池对照** | 中 | 同一题池、同一评分、预注册的“接受/拒绝记录表”，比较拒收理由而非分数 |

明确不做：

- 为了让 demo 好看而伪造 real-corpus 结果；
- 为了制造“改进”而故意答错（那会把门禁有效变成门禁被喂假数据）；
- 在 L1.5 之前宣称任何效应量。

## 9. 组会怎么说（三句话 + 四条边界）

**三句话：**

1. “FlashRSI 我完成了 L1 最小端到端：算法、harness、评分、选择门、产物落盘全部真实工作，12 次宿主调用零失败，平局被严格门拒收。”
2. “Harness² 我读的是机制，跑的是接缝：预算恒等式、选择与评分分离、tripwire、整树携带；桥接 10/10 通过，但分类是 simulation，不是能力增益。”
3. “三者正交：它管改进准入，它管候选准入，我们管结论准入。共同任务面已经具备，对照实验是下一步。”

**四条边界（主动说，不等问）：**

- EM=1.0 只证明管线与门禁，不证明效应量；
- `localqa` 是本地扩展，分数不可比榜单；
- token 全 0 是仪器缺口，不是零成本；
- Harness² 桥接是接口证据，不是“我们也把它跑通了”。

## 11. 最后一句

前几轮我把“真实”当成一条条可检查的约束：数字要有出处、委托签不能算人签、教学生成物要标示例。这一轮我想补上的是它的另一半：

**真实不只是“不夸大”，还是“敢让自己也被同一把尺子量”。**

FlashRSI 用 `accepted=false` 量了自己，Harness² 用 `R=4k` 量了自己。我们量别人很严，量自己还很松。下一步该补的，不是界面，是这一刀。
