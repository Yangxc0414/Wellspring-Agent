# 一键演示完整流程：演示播放器设计——回放已有转录，不制造新状态

> 状态基线：2026-11-20。承接 136–138（真实闭环进演示、逐会话就绪度、BRIEF 诚实性）、139（谁有权说更好）。
> 本文只改前端工作台（`apps/web`），不新增任何实验读数、不改 seed 数字、不触碰 CLI/模块契约。

---

## 0. 一句话结论

组会需要"一键演示完整流程"，但直接复用现有的 `startAuto` 引擎会向已完成的 seed 会话**追加**硬编码教学消息——这正是 137 修掉的"面板与会话矛盾"的复发路径。所以新做的演示播放器选择第三条路：**不执行、不追加、不伪造**，把已经通过逐会话校验的转录当作唯一剧本，逐步揭示 + 解说 + 阶段联动。

## 1. 问题：三个现有机制都不适合当"一键演示"

| 现有机制 | 为什么不能直接用 |
|---|---|
| `startAuto`/`advanceAuto` 引擎 | 向当前会话追加钙钛矿教学消息（RUN-014/T80 412）；在 `full-chain-demo` 上跑会把教学数据追加进已完整的转录，制造 137 式矛盾；在真实闭环会话上跑会污染真实回放 |
| FlowDemo 右栏 | 手动状态机（本地 React state），每步都要点；而且只是通用模板，不是"逐条消息"的演示 |
| 逐会话 seed 转录 | 内容自洽且经 137 核查，但没有任何"按阶段播放"的机制 |

结论：演示的**剧本已经存在且可信**，缺的只是"播放"这个动作层。

## 2. 设计：播放器是回放指针，不是执行引擎

**核心不变量（实现与测试都钉死）：**

1. 播放器状态只活在 `ui.demoPlayer`（不在 `persistedSnapshot` 里）——刷新即失，与 FlowDemo"模拟人签只在内存"同一纪律；
2. 播放器**绝不写 task 字段**：gates/evidence/claim/messages 全部只读，逐步揭示只是渲染层的 `messages.slice(0, revealCount)`；
3. 解说词（`DEMO_NARRATION`）只描述机制，**不引入任何新数字**；真实版引用的 0.956 / iris 150×4 / seeds 17,18,19 全部逐字来自 `runtime_data/e2e-closed-loop` 产物的转录原文；
4. S5b 人工门停点是特性：揭示到 S5b 消息即暂停。教学版提供「模拟人签（演示）」（内存态）；真实版**不提供**模拟人签——盘上那份是 autopilot 委托签（submission=false），再模拟一次"人签"会模糊 136 立下的区分；
5. 播放条常驻诚实边界行："回放已完成的会话：不调用模型、不执行实验、不写盘、不生成签名；右侧面板显示最终状态"——逐步揭示与右栏终态的时间差由此声明兜底，而不是等观众自己发现。

**两条主线**（用户已确认：教学版默认，可切真实版）：

| | 教学版 | 真实闭环版 |
|---|---|---|
| 剧本 | `full-chain-demo`（21 条消息，S1→META 九阶段） | `e2e-closed-loop`（13 条消息，七阶段） |
| 数据性质 | 演示数据 · 代理指标（页面上已标注） | 真实执行 + fixture 语料 + 委托签（三件事一起讲） |
| S5b 停点 | 模拟人签（演示）/ 继续 | 只能继续（附"委托签≠人签"提示） |
| FlowDemo 同步 | 受控：节点随揭示点亮（仅 teaching；real 时右栏自动回落到既有的"通用模板"警示） | 不同步 |

**交互模型**：消息逐条揭示（带卡片 4.2s / 纯文本 2.6s，`demoDwell`）；进入新阶段时解说条换词、教学版右栏节点点亮、进度 rail 更新；⏸/▶、按阶段步进（整段揭示/回退）、rail 点按跳阶段、随时退出；结束态给 重播/切换主线/退出。

**入口**（同一 action `startDemoPlayer`）：TopBar 主按钮「▶ 完整演示」、Sidebar 快捷格（改 2×2，新增"完整演示"）、欢迎页两个直接播放按钮（区别于只填入的示例 chips）、命令面板两项、设置-快速引导第一步。

## 3. 已实测

- `npm run typecheck` 通过；`npm run test:unit` 28/28（新增 `tests/demoPlayer.test.ts` 7 例：教学/真实阶段表、span 覆盖无遗漏、S5b 门停、dwell、解说词全覆盖、初始态）；`npm run build` 通过。
- 阶段表一致性有测试钉住：教学转录的 stage 标签序 == FlowDemo 的 `TEACHING_STAGE_IDS` 序（面板受控映射的前提）。
- 边界测试：`demoStageSpans` 覆盖首标签之后的全部消息（无标签尾消息归入最后阶段，按阶段步进不会隐藏它们）。

## 4. 设计主张（可证伪）

1. "回放式演示"比"重演式演示"（重跑 `advanceAuto`）更适合组会：剧本可信度来自 136–137 的逐条校验，而非新的硬编码；
2. S5b 停点 + 真实版不提供模拟人签，是把"谁有权说更好"（139）在演示层又钉了一次：网页上出现的任何"已签"要么标注 DEMO、要么标注委托签；
3. 阶段解说是"演示脚手架"而非证据：它只引用转录已有的数字（真实版）或不引数字（教学版），被 `demoPlayer.test.ts` 逐条核查。

## 5. 边界与不做

- 不改 `advanceAuto`/`startAuto`、ClaimGateDialog、claimSignature、任何 seed 数字；
- 演示态不写 task 的 gates/evidence/claim，不产生 signature.json；
- 静态构建与 runtime 模式行为一致（播放器是纯前端）；MCP/runtime 不暴露任何演示端点；
- 已知剩余差距（继承 139 §6 的清单）：没有任何会话拥有真实人签的完整闭环；真实版回放缺 S6/META 两段（其剧本本来就到 G5 为止）。
