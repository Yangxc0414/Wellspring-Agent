# ESE 完整闭环回放与会话阶段路径：每条历史会话都能讲完

> 状态基线：2026-11-21。承接 137（逐会话就绪度：ESE 当年只有 5/9）、138（BRIEF 同频）、140（演示播放器）、141（人工门对话化）、142（文献台账）。
> 本文只改前端工作台（`apps/web`）；ESE 全部数字逐字来自 `runtime_data/ese-ms-20261118-03` 产物与既有会话文本，不新增读数。

---

## 0. 一句话结论

组会演示还剩两处"断断续续"：ESE 这条**唯一真实仓库挖掘会话**停在 G5（无阶段标签、叙事戛然而止），右栏流程面板在任何非 full-chain 会话上都退化为通用模板。本轮把 ESE 补全为 **S1→META 全阶段诚实回放**（执行真实、未产出如实说、人签停点保留），把右栏改成 **会话阶段路径**——从当前会话自己的 stage 标签派生，点击节点直达该会话对应阶段的消息，演示播放时当前阶段自动点亮。

## 1. ESE 会话：从"停在某个阶段"到"讲完整个闭环"

补全前后对比：

| | 补全前（design/137 时点） | 补全后 |
|---|---|---|
| 消息 | 9 条，无 stage 标签 | 17 条，九阶段标签齐全 |
| 叙事 | 拆解→执行→读数→分层→G5 blocked，戛然而止 | S1 语料组装 → G1 收敛（新增）→ G2 冻结（新增）→ S5a 执行 → S5b 分层判定 → **S5b 门卡（新增，待人签）** → S6 如实"未产出结果图"（新增）→ S8–S12 locked（新增）→ S13–S16 闭包口 → META 经验登记（新增）→ 收束语 |
| 阶段计数 | 回放 5/9 | 回放 5/9（不变：S6 之后没有真实执行，计数不撒谎） |

诚实规则贯穿补全：S6 写"本轮未产出绑定 EA 的结果图（runtime_data/ese-ms-20261118-03 下没有 result-figure）"；S8–S12 写"claim 人签前不上数"；META 写"经验登记（引用必须带分层口径，与记忆 mem-seed-ese 一致），无可准入的参数改进，不生成自进化候选——经验 ≠ 能力增益"。**补全的是叙事，不是进度**。

配套改动：DEMO_LABELS 升为"真实研究·闭环回放 / 闭环·待签"；旧 localStorage 快照由 `ensureEseClosedLoop` run-once 迁移刷新（结构检测：消息无任何 stage 标签才替换，用户真改过的会话不被覆盖）。

## 2. 会话阶段路径：右栏节点 = 当前会话走过的路

FlowDemo 双模式重构：

- **SESSION PATH（转录带 stage 标签时默认）**：阶段列表由 `demoStagePlan(messages)` 从会话自己的标签派生——列表即这条任务走过的路；人工门徽标由 GATE_FOR_STAGE 映射（S2–S3→G1、S4→G2、S5b、S13–S16→G5）；点击节点/↗ 跳到该阶段第一条消息（`focusStage` 机制），节点必有真实跳转目标；演示播放器在**任何主线**上驱动时，当前阶段 `is-current` 高亮并自动展开（含后端契约块）。
- **通用模板**（无 stage 标签的示例任务）：保留手动推进/模拟人签的教学机，警示横幅不变。

两个防错细节：① 会话模式**不显示**目录里的"产物（示例）"数字（AUTO_STAGE_CATALOG 的 output 是教学示例，挂在 ESE 上就是 design/137 修过的"面板硬编码别的任务的数字"复发），只显示命令名 + 后端契约；② 会话模式不再渲染通用模板的 EVIDENCE CHAIN / WRITING SLOTS 演示卡（它们绑死模板的 signed 状态），治理状态以 BRIEF / RUN / EVIDENCE 为准。

## 3. 播放器第三主线 + 门停语义修正

- 新增 **ESE 闭环**主线（教学版 / 真实闭环 / ESE 闭环）：`allowDemoSign=false`（claim 未人签，盘上无 signature，模拟人签会伪造一次从未发生的越门）；逐阶段解说词全部引用会话已有数字（0.3749 / +0.0464 / p=0.015 / click 反转）；欢迎页三按钮 + 命令面板三项。
- **门停时机修正**（实测逼出）：原逻辑揭示到任意 S5b 标签消息即停，但 ESE 的 S5b 有两条带标签消息（分层判定 + 门卡）——停在第一条时门卡还没揭示。修正为"整段 S5b span 揭示完再停"（`demoStageSpans` 的 `span.last`）；教学/真实主线 S5b 单消息，行为不变（13/23 处停点复测一致）。

## 4. 已实测

- `npm run typecheck` 通过；`test:unit` 37/37（新增 ese 主线用例：taskId / 禁模拟签 / 九阶段解说全覆盖 / 主线序为三）。
- 浏览器实测：旧快照迁移自动刷新 ESE 会话（9 条→17 条、侧栏"闭环·待签"）；会话路径 9 阶段 + 门徽标；点 S4 节点 → 会话跳到 G2 消息并闪烁；ESE 主线播放 11/17 处门停（门卡已揭示、无模拟签）、播完 9 阶段完成；教学主线 13/23 门停（有模拟签）。
- 排障记录：一度观察到播放"卡顿"与"门停未触发"——根因是**隐藏标签页的 Chromium 定时器节流**（后台页 setTimeout 被强节流），并非代码缺陷；把标签页置前后复测，教学门停精确复现在 13/23。这条写进文档是因为它会影响任何用无头/后台页做播放验证的人。

## 5. 设计主张（可证伪）

1. "历史会话能讲完"的正确解是**补叙事不改进度**：ESE 的回放 5/9 计数不变，S6/META 的缺席在叙事里如实说——若把计数补成 9/9，就制造了 design/139 批判的"演示越门"；
2. 右栏的通用模板只该出现在"会话本来就没有阶段路径"的地方；一旦会话有自己的 stage 标签，面板必须讲这条会话的故事——否则每个新会话都在教育观众一个和它无关的模板；
3. 门停是语义事件（整段人工门揭示完毕）而不是文本匹配事件（看到某个 stage 标签就停）——多消息阶段的门停必须按 span 计算。
