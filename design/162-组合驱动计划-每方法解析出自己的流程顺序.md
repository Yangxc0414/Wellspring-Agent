# 组合驱动计划：每个方法从注册表解析出自己的流程顺序——"不同任务不同流程"的数据形态

> 状态基线：2026-11-21。承接 156（治理元模型+组合进注册表 0.4）、161（对比表收口）与用户补位（"对于不同的任务，想出来不同的思考方式、实验方式，而不是固定的一个流程"）。
> 本文实现组合驱动**计划**（python `stage_plan` + 前端镜像 + 上屏）；执行器消费计划仍为 SPEC 先行 roadmap（156 §4）。

---

## 0. 一句话结论

上一轮组合进了注册表但只是"被校验的数据"。本轮把它**解析成每方法自己的阶段计划**：`stage_plan(method_id)` 按方法绑定的组合接线顺序，过滤该方法的核心槽位，附上方法自己的槽位任务卡——**不同方法的计划顺序确实不同**（SLR：S0→S1→S1b→S8-S12，验证式；仓库挖掘：S1→S4→S5→S5b，探索式且假设后置）。这是"不是固定流程"第一次成为**可派生、可对比、可上屏的数据**，也是执行器迁移（156 §4）所需的中间产物。

## 1. 数据与派生（registry 0.4 → 0.5）

- **每方法 `composition_id`**：绑定到一种组合接线（SLR/受控/准实验/基准/调查 → 验证式；挖掘/案例/DSR/行动研究/ML 迭代 → 探索式）；
- **每组合 `slot_map`**：组合要素 → 治理槽位的桥（证据要素跨 S1 收集与 S5 执行；经验要素不映射治理槽位——它是循环，不属于 S0-S16）；
- **python `stage_plan(method_id)`**：按接线顺序走 slot_map，过滤 fit_stages，附方法自己的 stage_tasks；**组合未编排的 fit 槽位**（如 SLR 的 S1b——验证式接线无综合要素）按规范序补入并标 `uncovered`——诚实扩展缝；
- **前端 `stagePlanFor`** 镜像同一派生（消费同一快照），方法详情卡新增 **解析后的阶段计划** 块（组合标签 + 槽位序列 + 任务卡 + uncovered 标注）。

**校验升级（fail-closed）**：method.composition_id 必须指向存在的组合；组合 slot_map 必须覆盖接线要素且槽位在治理词表内；**方法的 fit_stages 必须被其组合编排覆盖**（否则拒绝加载）——这条新不变式保证"方法声明的槽位，其组合必须有走法"。

**排障记录**：validate 里本有一处 `stage_ids` 局部遮蔽（fit 校验"碰巧"工作在旧实现），加新校验后暴露——顺手中修为 known_stage_ids（151 同类问题再现：遮蔽是潜伏 bug 温床）。

## 2. 派生结果对比（数据说话）

| 方法 | 组合 | 解析计划（顺序） |
|---|---|---|
| 系统文献综述 | 验证式 | S0 → S1 → S1b → S8-S12 |
| 机器学习迭代实验 | 探索式 | S1 → S2-S3 → S4 → S5 → S5b → S6 → S8-S12 |
| 软件仓库挖掘 | 探索式 | S1 → S4 → S5 → S5b |

同一元模型，三种计划顺序——**"不同任务不同思考方式与实验方式"的数据形态**。切换方法详情卡即可并排对比计划。

## 4. 设计主张（可证伪）

1. **组合驱动计划是执行器迁移的中间产物**：一旦 pipeline.py 消费 stage_plan（SPEC 先行），"固定流程"即被替换为"注册表解析的计划"——本层的派生正确性已由 python 测试与前端双实现交叉验证；
2. **uncovered 标注是扩展缝**：方法声明了组合未编排的槽位（如 SLR 的 S1b），计划如实标出——这是"组合提案"（151/154 roadmap）的天然提案对象；
3. 绑定错误（方法绑定到不存在的组合）与覆盖缺失（fit 槽位无走法）都被加载器拒绝——**方法的元数据错误在数据层暴露，不到执行层才炸**。
