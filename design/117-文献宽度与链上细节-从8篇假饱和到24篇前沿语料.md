# 117-文献宽度与链上细节：从"8 篇假饱和"到 24 篇前沿语料 + 6 条候选

> 状态基线：2026-11-18。触发：用户指出文献检索太少、收敛不出合理 idea，要求换检索方式、按 1/3/6/12 个月 arXiv 前沿收敛，并反思"文献证据→假设与方案→本地实验→结果解析→结论签署→沿袭核对"各模块细节。
> 本轮交付：frontier 抓取（时间窗 + 多主题去重）、覆盖率语义修复、候选上限开放、24 篇真实语料跑通并对比。

---

## 1. 检索升级

`scripts/fetch_se_corpus.py` 新增：

- `--topics` 多主题（逗号分隔），合并去重（arXiv id）；
- `--months N` 时间窗（按 arXiv published 过滤，manifest 记录 cutoff）；
- 每查询保留计数、manifest schema 升到 `se-corpus-0.2`；上限 40 篇。

本轮实际抓取（6 个月窗口，cutoff 2026-05-22，24 篇）：

```text
per_query = {flaky test: 6, test co-change: 0, bug-fix commit: 5,
             regression test selection: 2, mining software repositories: 11}
```

两个直接观察：

1. **"test co-change" 在 cs.SE 近 6 个月里 0 命中**——这是词汇问题，不是没有相关工作（SZZ/测试共变用别的名字）；检索需要同义词扩展，而不是只改时间窗。
2. 24 篇里出现了 SZZBench、Stratum 等与"bug-fix 提交/测试证据"直接相关的前沿工作，候选 idea 明显被更新。

---

## 2. 两个真正的瓶颈（不是"文献太少"）

### 2.1 覆盖率把 8 篇判成"饱和"

`modules/literature.py` 的 TARGET_SOURCES=6 / TARGET_FULL_TEXT=3 / TARGET_SPANS=12 是**绝对值**；于是 `--max-sources 24` 但语料只有 8 篇时，仍报 saturated。

修复：saturation 改为**相对请求**（source_target = max(TARGET_SOURCES, requested)），并新增 gap `below_requested_sources:x/y`。测试更新：请求 7/语料 7 → saturated；请求 12/语料 7 → partial + gap。这一条让"饱和"不再骗人。

### 2.2 候选上限写死 3

`idea.max_candidates` 默认 3，pipeline 从未暴露。于是文献从 8→24、span 从 6198→15045，候选仍是 3 条。

修复：pipeline 新增 `--max-candidates`（1–8，默认 3）；idea SPEC 升 0.27.2。实测 24 篇 + max-candidates=6 → **6 条候选**，且出现 "SZZ label-definition sensitivity""flaky-test remediation confound" 这类只有读到前沿文献才会提的角度。

## 3. 三轮对比（真实运行）

| 运行 | 语料 | spans | 候选 | 覆盖 |
| --- | --- | --- | --- | --- |
| ese-fullrun（本轮前） | 8 篇 | 6198 | 3 | saturated（旧语义，虚） |
| ese-frontier（24 篇，cap 3） | 24 篇 | 15045 | 3 | saturated（cap reached，真到请求上限） |
| ese-frontier6（24 篇，cap 6） | 24 篇 | 15045 | **6** | 同上 |

结论：**宽度不是唯一变量**；候选上限和覆盖率语义会静默吞掉宽度收益。

## 4. 链上各模块细节反思

| 环节 | 现状 | 具体问题 | 建议 |
| --- | --- | --- | --- |
| 文献证据 S1/S1b | span-only、coverage receipt、Q0 | 无引文滚雪球（forward/backward）、无 venue 分层、arXiv 预印本、PDF-only、同义词未扩展、50 篇上限 | 加引文滚雪球与同义词表；把 venue/年份/评审状态写进 coverage；支持 CNKI/OpenAlex |
| 假设 S2/S3 | 候选帧 + falsification + 词法预审 | 警告里明确 "no_scientific_gap_in_s1"；novelty 未验证；候选上限吞宽度 | 从 gap pack 生成候选；引文最近邻找 prior art；候选数随宽度扩展（本轮已做） |
| 方案 S4 | design card + method registry 检查 | 检查在生成之后，模型看不到方法任务卡；metric/budget 形状仍不合格 | 把 method card 作为 designer payload；默认一次形状修复 |
| 本地实验 S5 | 两条路径：ML runner（EA/claim 链）与 ese_exec（capsule/EA） | pipeline 不消费 ese 胶囊；两条链未汇合 | pipeline --ese-study-dir 挂 S5 候选证据 |
| 结果解析 | result_interpreter 给 S5b 人类读者初步解读 | 只接 ML run 结果；解读需绑定区间/效应量 | 让解析器读 capsule 的 CI/差异；对 ESE 结果也生成解读 |
| 结论签署 | run claim；断言从 capsule 重算 | ESE 断言映射（107）只在执行器产物上验证过；pipeline 稿件路径无对应 | 统一 claim 模板：metric/CI/difference 三类断言 |
| 沿袭核对 | lineage 内容寻址 + stale 传播 | ESE capsule 尚未入 lineage；stale 传播未在 ESE 上测过 | 把 capsule/EA 作为 lineage 节点；加一条 stale 演练 |
