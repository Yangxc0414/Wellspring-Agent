## 状态与分段

| 区段 | 性质 | 维护规则 |
| --- | --- | --- |
| **00–44** | 早期设计与调研（v0 前后） | **冻结**：保留历史，不再修改；新结论写新编号 |
| **45–74** | 中期设计与实施记录 | 只修事实错误；不重写结论 |
| **75–120** | 当前阶段的反思、设计与整理记录 | 活文档：结论变化时在新文档里写"取代了 XX 的哪一条"，旧文档保留 |
| 组会纪要 | 会议记录 | 原文保留，不改写 |

**不删除历史文档。** 被取代的文档在首段标一行"状态：已被 XX 取代（日期）"，保留可追溯性；仓库体积靠 `scripts/repo_hygiene.py` 与发布清单控制，不靠删档案。

## 写作约定

1. 新文档从下一个编号开始，文件名 `NN-主题.md`（中文主题，与既有风格一致）。
2. 首段必须是：**状态基线（日期）+ 承接哪份文档 + 边界（本文改什么、不改什么）**。
3. 区分三类陈述：**已实测**（带命令/产物路径）、**设计主张**（可证伪）、**roadmap**（未实现）。不要把 roadmap 写成"已支持"。
4. 数值必须可追溯到文件或命令；示意值必须显式标注"示意"。
5. 不修改 00–44 来"适配代码"。代码服从 `modules/*/SPEC.md`；设计变更另开新文档。

## 与发布树的关系

`design/` 随 `python scripts/build_release.py` 同步到 `Wellspring-Agent/design/`（发行副本），因此本目录的文档必须不含本机绝对路径与密钥（`tests/test_release_surface.py` 会扫描）。
