# 86-真实模型跑通各阶段后的反思：哪些结果合理、哪些只是"结构上通过"

> 状态基线：2026-11-18。承接 81/83/85。
> 本轮用真实模型（AutoDL 网关 · DeepSeek-V4.1-Flash-1017）把 S1→S8 纵切实际跑了 8 次，逐阶段检查产物是否合理，并修掉 5 个在真实调用下才暴露的问题。
> 边界：API key 只进环境变量，不落盘、不进仓库；网关配置写在本机 `runtime_data/model_gateway.json`（gitignored），仓库代码不依赖该端点。

---

## 0. 结论先行

**"跑通"不等于"结果合理"。** 真实模型跑下来，四个阶段的表现分三档：

| 阶段 | 真实输出 | 判定 |
| --- | --- | --- |
| S1 规划 | 12 条子查询 + 6 个 facet（survey/method/evaluation/limitation/recent/中文） | **合理**：facets 覆盖了综述、方法、评测、局限、近期与中文来源 |
| S2–S3 想法 | 3 个候选，每个 4 条 span 证据、2 个来源，lens 分别为 mechanism/boundary/measurement；预审 2 advance / 1 revise | **基本合理，但有已知边界**：novelty 仍是 lexical unverified、open_slots 全空 |
| S4 设计 | 假设/基线/对照/预算齐全，但 **primary_metric 是一句话**、budget 是"Not specified…" | **部分合理**：结构通过、可执行性不足——旧清单只查"非空" |
| S8 写作 | 模型只写 Abstract/Related Work；Introduction/Discussion/Conclusion 因**编造数字**被拒 | **合理且护栏有效**：结果/方法保持确定性；但也暴露"静默回退" |

对应地，本轮修了 5 个真实问题（全部有测试）：裸 profile id 被静默忽略、模型来源不进产物、设计字段形状无人检查、idea 预审把"rankings/gaps"误判为无指标、写作模型静默回退 + 空内容错误不可诊断。

## 2. 各阶段真实结果与合理性判断

### 2.1 S1：文献规划

- 输出：12 条子查询，facet 覆盖 core/survey/method/evaluation/limitation/recent + 中文；4 个全文来源、1329 个 span；缺少 limitation/recent facet 时如实报 `missing_facets`。
- 判断：**合理**。规划层没有被"生成得多"诱惑：它按 facet 分组，并允许覆盖缺口显式出现。

### 2.2 S2–S3：想法

- 3 个候选，例如：
  - `Context adaptation versus base-model capability…`（mechanism）
  - `Bounded gains from recursive self-improvement…`（boundary）
  - `Separating scaffold effects from model effects…`（measurement）
- 每个候选 4 条 evidence_refs、2 个来源；带 falsification / kill_criteria / prior_art_delta。
- 预审：2 advance、1 revise（revise 原因是"无 metric/comparison 信号"）。
- 判断：**基本合理**。候选确实从证据出发、彼此 lens 不同；但：
  - `novelty_status=unverified`，prior art 只是线索；
  - `open_slots` 全部列出（variable/direction/metric/…）——**这不是缺陷，是设计要求**：想法阶段本来就不能替人填这些；
  - 预审的 revise 是一次**误判**（见 §3 F4）。

### 2.3 S4：实验设计

模型产出（节选）：

```text
hypothesis: For LLM agents evaluated on SE research tasks, observed gains are driven
            primarily by context adaptation and tool orchestration…
baseline:   Plain LLM without agent-system orchestration…
primary_metric: Comparative task performance of LLM agent systems versus plain LLMs
            on software-engineering research benchmarks.
budget:     Not specified in the provided evidence; define a small-scale budget…
```

`design-audit` 的判定是 `design.required: pass`——因为四个字段**非空**。但 `primary_metric` 是一句话、`budget` 没有可测口径，S5 根本无法执行。

判断：**部分合理**。这是本轮最重要的发现：**结构校验把"填了字"当成了"设计可用"**。

### 2.4 S8：写作

第一次跑：`paper.json` 的 `writer_mode=deterministic`，但 stderr 明明打印了 "paper writer: gateway profile …"。也就是说**模型被调用了、失败了、被静默回退**，产物里没有任何痕迹。

修复后（F5）再跑：

- `writer_mode=model`；模型写了 **Abstract** 与 **Related Work**；
- Introduction / Discussion / Conclusion 被拒，原因 `ungrounded_number`——模型在非结果章节里写了数字/结论，护栏生效；
- Results/Method 始终确定性生成，符合"结果不能由模型写"的边界。

判断：**合理且护栏有效**；但"失败必须可见"是这轮才补上的。

## 3. 发现的问题与代码修复

### F1 裸 profile id 被静默忽略（CLI）

- 现象：`--idea-model deepseek-v41` 输出 `unknown idea model 'deepseek-v41'; using rule-based candidates`，但退出码 0、结果里也看不出来。
- 根因：三个 CLI 选项要求 `profile:<id>`，裸 id 直接落到 fallback 分支。
- 修复：`_known_gateway_profiles()` 读取网关 store；若裸 id 存在则按 profile 解析（`cli.py`）；`profile:` 前缀继续兼容。
- 测试：`tests/test_model_profile_resolution.py`（5 例）。

### F2 模型来源不进入产物（证据链）

- 现象：`demo.json` 只有 `modules.*.status`，无法回答"这条 idea/design/paper 是模型写的还是规则生成的"。
- 修复：pipeline 解析模型时收集 `model_notes`（planner/writer/idea/experiment/support_judge），写入结果 JSON 与 `demo.json` 的 `model_notes` 字段。
- 边界：只加只读字段，不改任何模块的产物契约；逐模块 provenance 仍待加（见 §5）。

### F3 设计字段只有"非空"检查（S4）

- 现象：见 §2.3。
- 修复：`modules/experiment.py` 增加两个形状警告：
  - `primary_metric` 若含空格/句末标点/过长 → "primary_metric is a description, not a metric identifier"；
  - `budget` 若明确写 not specified 或没有任何数字 → "budget does not state a measurable budget"。
- 刻意**不改变 status 与门禁**：这类字段是否放行仍由 G2 的人决定；系统只负责让人看见。
- 测试：`tests/test_experiment_model.py` +2 例。

### F4 Idea 预审把"rankings/gaps"当成无指标（S2–S3）

- 现象：候选否证条件写 "the same model rankings and performance gaps persist" 被判 `needs_metric`。
- 根因：`TESTABILITY_RE` 词表缺 ranking/gap/outperform 等比较词。
- 修复：扩展词表；测试 `tests/test_idea_review.py` +1 例。
- 边界：仍只是词法预审，不提升为 novelty 判断。

### F5 写作模型静默回退 + 空内容不可诊断（S8 / gateway）

三层问题：

| 层 | 现象 | 修复 |
| --- | --- | --- |
| `Paper Agent` | writer 返回 None 时无 warning、`writer_mode` 仍是 deterministic | 记录 `model_failed` + 原因（失败/无输出/非对象三分支），并避免重复 warning |
| `paper_writer` 适配器 | JSON 解析失败直接返回 None；模型异常也返回 None | 非 strict 下抛 `ValueError`（带 sanitized 原因）；增加**一次** JSON 修复重试（带 `WRITER_REPAIR` 提示）；大 payload 下仍失败则明确报错 |
| `ModelGateway` | 空 content 只报 "provider returned no text content" | 错误信息带 `finish_reason`；若完成 token 达到 max_tokens，附 "raise the profile budget" 提示 |

修复后的真实失败链可读：

```text
section writer failed (ValueError: paper writer model failed: ModelCallError:
provider returned no text content (finish_reason=length, completion_tokens=4096 >= max_tokens=4096
(raise the profile budget))); deterministic draft kept
```

这正是本轮从"跑不通"到"跑通"的关键：**原因是 reasoning 模型把 4096 token 全花在推理上，content 为空**；把 profile 预算提到 16384 后，模型正常输出。

### F6（运行配置，不是代码缺陷）

- reasoning 模型在长 payload 下需要更大的 `max_tokens`；默认 4096 不够。已在 `runtime_data/model_gateway.json` 调到 16384，并在 `method`/文档中记录该运维经验。

## 5. 仍未解决的问题（诚实清单）

1. **逐模块 provenance 不完整**：`idea.json` 只有 warning 提示 "model_proposed_candidates"，`experiment.json` 只有 warning；真正的 `model/profile` 字段还在 `demo.json` 汇总层。下一步应给 idea/experiment/paper 三个产物加只读 `model` 字段（契约 minor，需评审）。
2. **novelty 仍是 lexical unverified**：真实模型想法的"新"没有与文献做语义比对；这是 design/83 的 held-out 任务与真实 prior-art 检索要解决的。
3. **idea 预审是词法规则**：F4 只是把误判减少，不是把预审变成质量判断；未来应接模型 critic 与 held-out 评估。
4. **设计字段的"可执行性"只到 warning**：是否把 metric/budget 形状升级为 G2 blocker 是产品决策，需要人工确认（门禁变更）。
5. **写作只覆盖非结果章节**：这是正确边界，但也意味着"论文质量"的大部分仍靠人；模型能帮的只是结构、语言与相关工作。

---

## 6. 一句话总结

真实模型把三类问题照了出来：**调用成功但来源不可见（F1/F2）**、**结构完整但不可执行（F3）**、**失败可见性不足（F5）**。修完之后，系统至少能做到：每一次阶段产出，都知道"是不是模型写的、写坏了没有、坏在哪"。这比"跑通"更接近可用的自改进科研智能体。
