# 研究方法形式化建模：护栏（硬性约束）与可优化策略空间的二分

**状态基线（2026-11-22）**：承接 design/171（四层模型）、172（八分类审计）、174（方法真正剪裁阶段）。
本文落实导师框架的核心指正：**自改进的上限取决于对"研究方法"的形式化抽象程度**——
我们此前只建模了"护栏"，没有建模"可优化空间"，所以自改进只能改 skill，改不了流程。

---

## 1. 核查：导师框架 hit 中我们的真实缺口

把导师的两层框架映射到现有系统，逐条核查（带代码证据）：

| 导师框架 | 我们已有的 | 缺口 |
|---|---|---|
| 纵向：研究阶段（时序） | `stages`（10 槽位）、`composition.wiring`（步骤+rationale）、174 真剪裁 | 顺序仍按物理序，未按 wiring 重排（174 已声明） |
| 横向：研究方法（范式） | 10 方法 × `protocol_fields/checks/guidelines/cannot_support/iteration_rule` | **全部是护栏字段，无"可优化策略"字段** |
| 阶段 × 方法 = 子任务 + 方法论约束 | `stage_tasks`（每方法 5 项文本）、`method.card` | 格子只有一句 task 文本，未分"硬约束 / 可选策略 / 校验指标" |
| 硬性约束 AI 不能改（护栏） | `LOCKED_SCOPES` 8 项、`checks.severity=blocker`、`iteration_rule` | 已扎实，且 fail-closed（但分散在多处，没有统一视图） |
| 可选策略分支 = 自改进空间 | `GENERATION_EFFECT_KINDS` 仅 3 种（lens diversity / demote / carry falsification），全在候选生成层；租约可改面只有 `retrieval.budget` / `run.seeds` / `harness2.harness` | **没有任何"方法策略面"：阶段路由、子任务增删、执行策略切换都不在可改清单里** |
| 自改进对象含"任务间调度/分支策略" | feedback → generation constraints（L1 候选层）；Harness² 组件面（工具层） | 调度/分支策略没有可改的句柄——不是机制不支持，是**没建模出可改的东西** |

**一句话**：老师的判断准确——"建模只到读文献/写代码/跑实验"那层，AI 就只能改 skill；
我们建模到了范式层（护栏），但**没有把"范式允许的自由空间"显式化**，所以流程级自改进无对象可改。

---

## 2. 形式化模型：每个方法的"约束空间 / 策略空间"二分

给每个方法建一个三元组（不塞进现有 schema，作为独立只读视图）：

```
MethodStrategySpace = {
  method_id,
  hard_constraints: [ 护栏：来自 checks(blocker) + protocol_fields + cannot_support + iteration_rule.kind
                       + LOCKED_SCOPES 交集 ],
  choice_points: [
    { id, stage, description,
      options: [ 可选策略 ], 
      default: 默认策略,
      guard: 不得违反的护栏 id 列表,
      reversible: 是否可回退,
      evidence_of_effect: 如何判定该选择更好（校验指标） }
  ],
  boundary: 明确写出「哪些不属于本方法/不可优化」
}
```

### 2.1 形式约束（fail-closed，可机器校验）

1. 每个 `choice_point.guard` 必须引用真实存在的护栏 id（blocker check / LOCKED_SCOPES id），未知 id 拒绝；
2. `options` 中任何一项不得**包含** `cannot_support` 类措辞对应的行为（如受控实验不得出现"事后改主指标"）；
3. `choice_points` 只落在 `fit_stages` 内；阶段外不得有策略点；
4. 策略点不得触碰 LOCKED_SCOPES（claim.statement / evidence.artifact / gate.decision / rubric / heldout / closure / signature / export）；
5. 每个策略点必须有 `evidence_of_effect`——否则"优化"无法被判定，是假自改进。

这五条把老师说的"护栏 vs 可优化空间"从一句原则变成**可校验的数据契约**。

### 2.2 每个方法至少要有几个策略点（首批，逐字有据）

- `controlled-experiment`：
  - S4 `randomization.scheme`（简单随机 / 区组 / 分层）—— guard: `experiment.design`, `experiment.power`；默认区组；
  - S5 `measurement.instrument`（同一构念的替代量表/计时方式）—— guard: 主指标不得事后改；
- `case-study`：
  - S1 `data.collection`（访谈 / 观察 / 文档，可组合）—— guard: 三角验证不得退化为单源；
  - S5 `coding.frame`（开放编码 / 预定义编码本）—— guard: 证据链完整；
- `repository-mining`：
  - S1 `sampling.frame`（时间窗 / 语言 / 活跃度分层）—— guard: 快照 sha 固定；
  - S5 `label.heuristic`（关键词 / 提交信息模式）—— guard: 构造效度检查；
- `systematic-literature-review`：
  - S1 `query.expansion`（同义词 / 布尔式 / 逆向引用）—— guard: 检索可复现；
  - S1b `synthesis.method`（主题综合 / 元数据计数）—— guard: 每主题 source_count≥2。

**注意**：这些是**建模示例**，不是"已经能动态执行的策略"。本文只建"空间"，执行与租约是下一步。

## 3. 与现有自改进机制的关系（不重叠、不冲突）

```
现有（L1 / 工具面）：
  feedback → generation_constraint（候选生成策略）
  Harness² → 组件面（skill / prompt / tool）
  lease → 预算面（retrieval.budget / run.seeds）

新增（L2 / 方法策略面）：
  strategy_space.choice_points —— 在范式护栏内，策略点可取哪个 option
  ↑ 这一层此前不存在，所以"流程级自改进"没有对象
```

三层各自改的东西互不越界：`strategy_space` 的 guard 直接引用 `checks` 与 `LOCKED_SCOPES`，
因此**策略的优化永远不会改写护栏**——这正是老师强调的"全程不能突破底层规范"。

---

## 4. 为什么不做成 method-registry schema 的字段

把 `strategy_space` 作为**独立只读视图**（`method-strategy-space.json` + 领域模块），理由：

1. schema 0.7 的 method 对象已有 20 个字段，塞入策略空间会触发契约 minor 升级，且必须人工确认（AGENTS.md §60）；
2. 护栏的**权威源**仍是 `method_registry.py` 的 validate + `checks`，策略视图只是引用它们，不复制、不覆盖——保持单一事实源；
3. 独立文件可独立演进（先建空间，再接租约、再接执行），不阻塞现有 10 方法与前端。

代价：两个文件需要一致性校验（本文用 fail-closed 规则 1–5 保证），这是可接受的工程债，已明确记录。

---

## 5. 可证伪主张

1. 若某策略点的 option 违反其 guard，`validate_strategy_space` 必须拒绝加载——可写负例测试。
2. 若把 `choice_points` 接到租约面，自改进提案第一次能**改变阶段内的执行策略**（而非仅 skill/预算）——待实现后可测。
3. 若模型太粗（only 护栏 no 策略），自改进只能改 skill；本模型把策略点显式化后，才可能做流程级改进——这是本轮的立论，可由"提案是否引用 strategy_point_id"验证。

---

## 6. 边界

- 本轮**不改注册表 schema**、不改 pipeline 执行、不改门禁、不改 Harness²。
- 策略点是**可选项的声明**，不是"AI 现在就能自动选"——自动选择要接租约/评测，属下一轮。
- 首批只填 4 个方法的策略点（示例性覆盖四种范式），其余方法标记 "pending"——不假装已全建模。
