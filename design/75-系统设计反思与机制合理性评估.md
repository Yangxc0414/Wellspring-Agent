# 75-系统设计反思与机制合理性评估

> 状态基线：2026-11-15。本文是对全部机制的一次批判性复审：哪些经得起追问、哪些不合理、如果重来会改什么。判据全部指向已落盘的实测与仓库事实，不做泛泛的优点列表。

## 1. 总判断

**语义层（门禁、证据链、判定）是稳的；真实缺口集中在测量层与供给层。** 具体说：门禁语义、旁路产物隔离、读时重算、准入谱系这些"定义"层面的设计经得起追问；但**人签质量无仪器、反馈环效果未测量、独立验证名不副实**三个缺口是真实存在的——它们都是"测量/供给"缺口而非"语义"缺口，即：语义定义对了，但语义执行的质量没有被系统看见。

## 2. 经得起追问的机制（四个，各附理由）

### 2.1 旁路产物不进主链
LLM 连接器（预评估/解读/span 分级）输出永远写旁路文件，主链六环纯人工签核。这条设计的强度在于：**混进主链一次，整条链的可信度语义就被稀释，且不可逆**。用结构（写路径不存在）而不是纪律（提示词约定）来保证，是正确的选择。测试钉住了"no claim/gate/signature"边界。

### 2.2 verdict 两态 + underpowered 守卫
M1/M2 的 verdict 只有 supported/not_supported，not_supported 如实落盘；多会话 n=3 时守卫输出"too few to interpret a sign"。这两个守卫在真实运行中**实际触发过**（不是摆设）——预注册判据先于跑数，是"自证"的最小可信版本。

### 2.3 读时重算（recompute over snapshot）
把"判定同步状态"问题改写成"消除状态"问题：verdict 是从不可变产物重导出的函数值，快照只是兜底，冲突由总线裁决上屏。这消掉了快照/产物/UI 三方不一致这一整类 bug。

### 2.4 委托的授权结构
autopilot 策略只能人写（scope/数据集/种子/有效期 + SHA-256 绑定 + [delegated:autopilot] 理由 + 越界即停 + agent 不能创建或放宽）。把"自动化边界"做成文件格式而不是开关，是可以对审计解释的设计。

## 3. 真实缺口与不合理之处（按严重度排序）

### 3.1 人签质量无仪器（最严重）
四门的语义强度全部锚在"人签"上，但系统**不测量签核质量**：评审者是否真的打开了预评估、看了多久、是否理解断言的数值边界，一概无记录。自动模式跑多了，人签存在疲劳退化为橡皮图章的结构性风险——届时整条链退化为"有人按过按钮"。
**改法**（轻量可行）：签署前必答检查点（如要求确认断言数值边界才能点签署）+ 记录签核会话的查看路径；更进一步可测"签核稳定性"（同一批材料隔期重签的一致性作为信度读数）。

### 3.2 单人系统的结构性循环
验收单元是 signed commission，但唯一的签核者是系统作者本人——门的人工性在单人场景退化为"不同时间点的同一个判断者"，G2 冻结的独立性不成立。
**缓解**：G2 已有预注册纪律（判据先写死）；但引入第二签核者（导师/同学）作为流程要求、以及把"签核一致性"作为读数，是诚实的补法。这一点应在面试与文档中主动承认，而不是藏住。

### 3.3 反馈环有效果语义、无效果测量
四个反馈环（lineage_reverify / t6b_falsification / belief_revision / homogeneity）约束下一次生成，但**"约束是否改善产出"没有 M1/M2 式测量**。闭环的最后一环（效果验证）缺失。
**改法**：给每个环做有约束 vs 无约束的成对生成对比（复用 M2 的方法学），判据预注册。

### 3.4 independent_verify 名不副实
M2 的 independent_verify_then_store 在同宿主环境里，验证者与提出者共享宿主模型——"独立"只做到了流程独立，没有做到供给独立。真正的独立验证需要跨供给（host-as-model 多供给），而当前实测环境只有 Zcode 可用。
**承认的边界**：设计文档已写"供给多样性 ≠ 模型多样性"；但 M2 的 verdict=supported 只支持"四策略判别"，不支持"哪个策略带来更好下游表现"——后者才是准入机制的最终问题，尚无测量。

### 3.5 宿主作答的传输层是人工的，无完整性校验
M2 多会话实验中，turn prompt 由人工转发给第二会话——实际发生了截断失真（漏了 IDEA-04，被评审守卫拒绝后重做）。messages_sha256 绑定的是 ledger 里的请求，但**宿主收到的题面是否完整没有机械校验**。
**改法**：宿主作答走已建好的 OpenAI-compat shim（HTTP 路径，请求以 ledger 为源），而不是人工复制粘贴；shim 已在（zcode_llm_shim），M2 没走它是流程选择而非能力缺口。

### 3.6 M1 的 35% 未解释
verdict_action_coverage = 0.6452：31 个 run 中约 11 个无 verdict 动作。这 35% 是"语义上无需动作"还是"链路缺口"，测量报告没有分解。**自己的读数没有被自己解释**——测量做了，解释没跟上。
**改法**：per_run 分解无动作原因（正常完成 vs 缺口），补进 M1 报告。

### 3.7 多文件无事务
write_json_atomic 保证单文件原子写，但 capsule+EA+claim 的多文件一致性没有事务层；中断窗口存在半更新状态。单人串行使用可接受，并行会话写同一 project 会竞争。
**改法**：同批次产物先写临时目录再整目录 rename（目录级原子性）。

### 3.8 边界内的经济性问题
span-only 边界（摘要不是证据）语义正确，但经济后果已在读数里：语料覆盖 thin（3/6 facets）。系统输出 coverage gap，但"gap → 主动补全文"没有闭环（fetcher 存在但不被 gap 驱动）。
**改法**：gap-driven fetching——覆盖缺口自动变成下一步获取动作的建议队列，仍由人批准。

## 4. 边界认识：三个"不是"要说清

1. **内容寻址不是防篡改**。SHA-256 绑定防意外损坏与无意篡改；MANIFEST 与产物同仓同机，有动机的重写可以同时改两者。系统提供的是**完整性检测**，不是防篡改证明——后者需要外置锚（远端第二副本/时间戳）。
2. **dispatch 计数不是门禁**。ExecPort 的 begin/end 是记账与未注册 kind 拒绝，执行授权仍在 CLI/人。上屏的是遥测，别读成治理。
3. **多会话不是模型多样性**。同模型两个会话剔除的是上下文污染，不剔除模型系统性偏差；跨宿主供给才是更强的去偏差。

## 5. 如果重来会改的三件事

1. **更早建立测量文化**：M1/M2 式预注册测量应该从第一个模块就有，而不是系统成形后补——后补时只能测"机制可区分"，测不了"历史决策质量"。
2. **更少的模块数**：35 个模块对单人维护偏多；closure/lineage/maintenance 的边界在现场多次需要来回查证。单人项目里，模块数量应与"能被一个人完整心算的子系统数"对齐。
3. **先定判定总线，再定各模块判定语义**：判定语义是后补的，出现过语义漂移，最后靠单点投影收敛。若先有 verdict-ledger 的 schema，各模块第一次实现就能对齐。

## 7. 结论

机制主干合理，且有真实运行证据支撑；三个最深的缺口（人签质量、反馈效果、独立验证）都不是语义错误，而是**系统的手伸不到自己某些决策环节的质量上**——下一步的改进方向不是加门禁，而是给已有的门与环装上测量。这与博士议程（governed self-evolution 的因果归因与准入证据）是同一条线：治理的下一步是测量的精细化。
