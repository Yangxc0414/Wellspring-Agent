## 3. 技术指标 6 条对照

1. **总体设计+模块规格+双入口+稳定** ✓：35 模块 SPEC（frontmatter 契约+changelog）、ARCHITECTURE 分层；CLI 与界面均可调用。稳定性注脚：CI 历次全绿，Windows 本地偶发失败（74 §8 记 1/3）；今日全量读数见 §5。
2. **溯源+上游变更→标记+暂停导出** ✓：MANIFEST 哈希绑定（数据/代码/执行记录）、`lineage impact --fail-on-stale`、篡改实测触发 export_allowed=false；代码版本=agent_tree_sha × platform_fingerprint 互链。**局限须写明**：内容寻址是完整性检测，不是防篡改证明（75 §4.1，需外置锚）。
3. **结构化+非法拒写+数值非模型生成** ✓：contracts dataclass+形状校验（拒写留 pending）；revision 数值只从用户表格与 spec 重算；writing_audit 结果数值边界；宿主答案形状校验（host_model._validate）。
4. **准入门+复用条件/适用域/验证记录+撤销+不改权重** ✓：lease scope、准入谱系、验证记录绑定、撤销传播；无任何训练路径（host-as-model/外部 API 均冻结权重）。
5. **人工确认+证据闭合链** ✓ 语义：G1/G2/S5b/G5 只能 CLI 人签；autopilot 必须人写策略（SHA-256 绑定+越界即停+agent 不能创建/放宽）；claim/evidence/signature/lineage 可核对（closed-loop bundle 齐全）。**两个诚实缺口**：单人系统唯一签核者=作者（75 §3.2，独立性弱，需第二签核者流程）；真实案例人签未做（§4）。
6. **完整案例+离线测试+演示/实证区分+负结果** ◐：demo 闭环 bundle 完整（fixture 显式标记：bibliography/bound/claim/closure/lineage/protocol/run/signature）；负结果保留机制在运行（not_supported/underpowered/失败 run 落盘，今日 FlashRSI 首跑失败目录亦保留）；**真实语料案例差一次人签**（§4）；测试读数见 §5。

## 7. 局限章必须如实写的（任务书"不把未实现写成已支持"）

- 单人签核：门的人工性在单人场景退化为"不同时间点的同一判断者"（75 §3.2）。
- 宿主同供给：host-as-model 的"独立验证"是流程独立而非供给独立（75 §3.4）；今日 FlashRSI 跑通的模型供给=宿主会话，非外部 API（76 §2）。
- 测量缺口：人签质量无仪器、反馈效果未测量、宿主供给成本无仪器（75 §3.1/3.3、76 §5）。
- 完整性≠防篡改（75 §4.1）；dispatch 计数≠门禁（75 §4.2）。
- Windows 偶发测试失败与无 Docker 限制（74 §8、76 §2.1）；未实现项（gap-driven fetching、目录级原子写等）列后续工作。
