# 104-控制变量落地：分层分析暴露的异质性与一个退化层

> 状态基线：2026-11-18。承接 103（五个缺口，第一个就是"controls 未进入执行"）。
> 本轮把 S4 的 controls 真正映射进执行器：按项目、提交大小、是否同时改生产文件分层，并给出 Mantel-Haenszel 调整差。
> 边界：探索性；标签仍是启发式；没有 Claim/EA/签名。

---

## 1. 做了什么

`ese_exec` 的执行结果新增 stratified 段：

- **project**：click / requests / httpx；
- **commit_size_bucket**：1–2 文件 / 3–5 / >5；
- **production_cochange**：提交是否同时触碰非测试的 `.py`；
- 每层给 bug-fix 与非 bug-fix 的 co-change 率与差值；
- 用 Mantel-Haenszel 风险差权重（w = n1·n2/(n1+n2)）给出**调整后差值**；
- 新协议 `ESE-MS-20261118-03` 把 stratification 写进 `analysis`，可复跑。

---

## 2. 真实结果（3 仓库、5132 次源码提交）

未调整：bug-fix **41.4%** vs 其他 **36.7%**，差 **+4.6pp**（置换 p=0.015）。

**调整后（Mantel-Haenszel）：+6.8pp。**

分层读数（关键几行）：

| 层 | bug-fix | 其他 | 差值 |
| --- | --- | --- | --- |
| project = requests | 0.358 (169/472) | 0.251 (591/2352) | **+0.107** |
| project = httpx | 0.626 (57/91) | 0.584 (519/889) | +0.043 |
| project = click | 0.438 (126/288) | 0.444 (462/1040) | **−0.007** |
| size = 1–2 文件 | 0.324 (219/677) | 0.253 (768/3039) | +0.071 |
| size = 3–5 文件 | 0.789 (120/152) | 0.636 (534/839) | +0.153 |
| size = >5 文件 | 0.591 (13/22) | 0.670 (270/403) | −0.079 |
| production_cochange = yes | 0.334 (250/749) | 0.275 (1025/3734) | +0.059 |
| production_cochange = no | 1.000 (102/102) | 1.000 (547/547) | **0.000（退化）** |

## 3. 两个必须写出来的发现

### 3.1 一个"控制变量"在定义上就是退化的

`production_cochange = no` 这一层里，两组的 co-change 率都是 **100%**。原因是构造性的：单位要求提交至少改一个 `.py`；"没有生产文件变更"意味着所有 `.py` 都是测试文件，于是 outcome 必然为真。

这不是发现，是**标签定义的假象**。处理：把两组都为 0% 或 100% 的层标为 degenerate，从 MH 调整中剔除；剔除后调整差从 +6.54pp 变成 **+6.81pp**。若不剔除，这个退化层会以很大权重把调整差拉向 0。

### 3.2 效应是异质的，不是"普遍规律"

- requests +10.7pp、httpx +4.3pp，但 **click −0.7pp（无差异）**；
- 提交大小 3–5 文件 +15.3pp，但 >5 文件 −7.9pp；
- 未调整的 +4.6pp 是异质效应的加权平均，**不能表述成"Python 项目的 bug-fix 提交普遍更常改测试"**。

这正是"执行真的做了分层"才会暴露的东西——只做合并比率是看不到的。
